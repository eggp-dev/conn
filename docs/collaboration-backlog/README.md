## 기록 원칙

- 테스트마다 [템플릿](TEMPLATE.md)을 복사해 `YYYY-MM-DD-short-name.md`로 기록한다. 같은 날 여러 세션은 별도 파일로 남긴다.
- 관찰에는 고유 ID를 붙인다. 사용자의 말, 실제 도구 결과, 해석, 미검증 사항을 구분한다.
- 과거 결과를 새 결과로 덮어쓰지 않는다. 재검증 날짜·환경·결과를 덧붙인다.
- 실패와 사람의 보정도 성공 결과만큼 중요하다. 누가 무엇을 바꾸었고 에이전트가 어떻게 이어갔는지 기록한다.
- 암호·키·토큰·인증 입력·원본 터미널 덤프는 저장하지 않는다. 개인 계정·주소·경로는 재현에 필요한 구조만 남긴다. 스크린샷·영상도 공개 전 별도 검토한다.
- 한 번의 성공은 다른 OS, 배포판, 보안 경계 전체의 검증으로 일반화하지 않는다.
