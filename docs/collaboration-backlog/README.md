# Collaboration test backlog / 협업 테스트 백로그

실제 사람–에이전트 협업을 세션 단위로 축적한다. 관찰에서 버그 후보와 제품 가설을 도출하되, 이 문서는 확정된 로드맵이나 수정 완료 목록이 아니다.

## 기록 원칙

- 테스트마다 [템플릿](TEMPLATE.md)을 복사해 `YYYY-MM-DD-short-name.md`로 기록한다. 같은 날 여러 세션은 별도 파일로 남긴다.
- 관찰에는 고유 ID를 붙인다. 사용자의 말, 실제 도구 결과, 해석, 미검증 사항을 구분한다.
- 과거 결과를 새 결과로 덮어쓰지 않는다. 재검증 날짜·환경·결과를 덧붙인다.
- 실패와 사람의 보정도 성공 결과만큼 중요하다. 누가 무엇을 바꾸었고 에이전트가 어떻게 이어갔는지 기록한다.
- 암호·키·토큰·인증 입력·원본 터미널 덤프는 저장하지 않는다. 개인 계정·주소·경로는 재현에 필요한 구조만 남긴다. 스크린샷·영상도 공개 전 별도 검토한다.
- 한 번의 성공은 다른 OS, 배포판, 보안 경계 전체의 검증으로 일반화하지 않는다.

## 다음 세션 후보

- 경로 외의 보정: 잘못된 브랜치·실행 옵션을 사람이 고친 뒤 중복 입력 없이 재개하는가?
- 보정 중 SSH 연결이 끊기면 에이전트가 로컬 셸로 돌아온 사실을 인지하는가?
- 에디터·비밀번호 프롬프트·원격 셸 사이의 전환에서 기록 범위와 제어권이 적절한가?
- 로컬 SSH 실행과 원격 작업을 타임라인에서 구별할 수 있는가? 인증 입력은 수집하지 않는가?
- 같은 시나리오를 배포판과 다른 에이전트로 반복했을 때도 자연스럽게 이어지는가?

세션이 누적되면 반복 빈도, 작업 중단 정도, 복구 비용, 사용자의 표현을 함께 검토한다. 그때 버그 이슈·제품 실험·데모로 전환하고 원래 관찰 ID를 연결한다.
