# 0.8.7 릴리스 검증

[English](release-0.8.7-validation.md) · [Mac 인수 검증](shared-runtime-macos-validation-results.ko.md) · [제어 UX 원칙](control-experience.ko.md)

2026-09-23. 릴리스 후보 소스의 검증 기록이다. 네이티브 빌드·서명·공증·배포는
해당 태그의 GitHub Actions와 공개 산출물에서 별도로 확인하며, 이 문서에서 미리 성공으로 선언하지 않는다.

## 이번에 반영한 내용

- 데스크톱과 웹은 같은 Svelte 컴포넌트·룬, owner 계약, 세션·PTY·정책 엔진을 사용한다.
  웹은 별도 로컬 호스트이며 데스크톱 세션을 복제하지 않는다. Linux x64 웹 배포 묶음에는
  서버·같은 빌드의 MCP CLI·공통 UI·빌드 정보·체크섬이 포함된다.
- 연결 요청은 터미널 위에 공간을 확보한다. 제어 요청은 오른쪽 Conn 배지에서 펼쳐지고,
  명령 승인은 하단에 유지한다. 접기·Escape는 거절이 아니며 요청은 배지에 남는다.
  자동 펼치기는 입력 포커스를 빼앗지 않고, 알림 이동은 승인하지 않는다.
- 승인 사유와 가능한 범위를 요청 자체에 고정했다. 늦은 상태 조회가 같은 요청의 버튼을
  바꾸지 않는다. 프로필·전경 프로세스가 달라지면 오래된 허용을 거절하고 현재 정책을 재검사한다.
  넓은 범위의 허용은 별도 펼치기 안에서 선택하며, 확인되지 않은 셸에서는 제공하지 않는다.
- 실제 전경 실행 파일로 SSH 여부를 확인한다. 인자·환경·인증 내용을 읽지 않는다.
  단독 SSH와 `printf ...; ssh ...` 복합 진입을 실제 OpenSSH에서 검증했다.
- 사람 입력 원문을 저장하지 않고 빈 프롬프트의 보이는 화면 경계를 추적한다. 빈 줄에서
  이동·삭제·화면 정리 키를 눌렀다고 에이전트를 막지 않는다. 입력을 지운 뒤 화면이 실제 빈 경계로
  돌아왔을 때만 회복한다. Home → Ctrl-U로 남은 뒷부분을 빈 줄로 오판하지 않는다.
- Mac 긴 입력 교착 수정을 유지하고, 큐에 도착한 출력보다 프로세스 종료가 먼저 전달되는 문제를
  수정했다. Linux에서는 WebKit 렌더러 우회 설정을 기본 적용하되 사용자의 명시적 설정을 존중한다.
- 브라우저에서 포커스 이동 뒤 앱 전체가 가로·세로로 밀리는 현상, 연결 카드가 메뉴를 가리는 현상,
  작은 창에서 제어 버튼이 가려지는 현상을 직접 발견해 수정했다. 사용자 Mac 게이트웨이의
  화면 문제까지 동일 원인으로 확정한 것은 아니다.

Rust 숫자에는 네이티브 Tauri가 포함되지 않는다. 설치되지 않은 zsh 경로는 내부적으로 생략했다.
SSH는 사용자 서버가 아닌 폐기 가능한 루프백 서버다. 첫 실행은 픽스처의 비 UTF-8 로케일 때문에
한글 검사에 실패했고, `C.UTF-8`로 바로잡은 뒤 전체 통과했다. 모든 원격 로케일에 대한 보장은 아니다.

느린 소비자 회귀 검사는 기본 4 MiB를 처리한다. 별도 64 MiB 검사에서는 출력 콜백마다 3ms를
지연시켜도 20.61초에 전체 바이트와 마지막 마커를 종료 이벤트보다 먼저 확인했다.
최대 RSS는 88,508 KiB였으며 시험 데이터 할당을 포함한 프로세스 전체 수치다.
큐는 여전히 무제한이다. 생산이 소비보다 계속 빠르면 메모리가 증가할 수 있으며,
이 유한 부하 검사를 무제한 출력 안전성 보장으로 해석하면 안 된다.

[스크린샷과 체크섬](validation/release-0.8.7/)은 합성 세션만 담는다. 1280×800과
640×420·동작 줄이기 조건을 비교했다. 인앱 브라우저에서도 1280×720에서
펼치기·접기·다시 열기·거절과 입력 포커스를 확인했다. 선택한
[모션 참고](https://motion-primitives.com/docs/morphing-dialog)는 표면의 연결된 전환만 적용하며,
램프 이미지·중앙 모달·배경 흐림을 복제하는 요구는 아니다.

## 검증 한계

기존 Mac 실기 결과는 `5df5e36` 기준이다. 새 제어 UI와 이번 추가 코어 수정은 이 Linux 세션에서
물리 Mac으로 다시 조작하지 않았다. Mac CI·서명·공증·Homebrew 설치 검사는 실제 협업 UI 검증과
구분한다. 사용자 고유 게이트웨이, 물리 IME 조합, 네이티브 알림 센터와 네이티브 IPC 장애 주입은
미검증이다. 로컬 GTK 개발 패키지는 없어 네이티브 컴파일은 CI의 플랫폼별 검사로 확인한다.
원격 웹 운영·서버 재시작 후 기존 PTY 복원·권한 자동 복원을 제공한다고 주장하지 않는다.
