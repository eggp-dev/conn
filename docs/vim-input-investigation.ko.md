# 0.8.7 macOS Vim 입력 장애 조사

[English](vim-input-investigation.md) · [검사 실행법](browser-testing.ko.md#실제-vim-편집-회귀-검사)

2026-09-23. **미해결: 사용자 macOS 네이티브 앱의 장애를 아직 재현하지 못했다.** 수정 완료나 재배포 근거로 사용하지 않는다.

## 제보와 기준

사용자는 업데이트 전 같은 작업 환경에서 vi로 파일을 편집했지만, 최신 Conn에서는 Vim에서 Esc → i → 영문 입력에도 반응하지 않는다고 보고했다. 일반 셸도 함께 멈추는지, 화면만 정지하는지, 포커스가 유지되는지는 아직 구분되지 않았다. 실제 사용자 파일·인증 정보·원격 세션은 조회하거나 변경하지 않았다.

검토 기준은 배포 태그 `v0.8.7`과 `v0.8.6`이다. 로컬 검사 체크아웃은 `05b6214`이며 v0.8.7에 포함된 소스다. 제품 코드에는 추측에 따른 수정을 하지 않았다.

## 코드에서 확인한 것

- `Session::human_input`은 사람 입력을 PTY로 전달한다. 새 `HumanInput.pending`은 사람의 키 입력을 직접 거부하는 조건이 아니다.
- 공통 Term은 `renderReady` 또는 `backendOnline`이 거짓이면 입력을 전달하지 않는다. 이 준비 상태와 네이티브 출력 구독·체크포인트 전달 경로는 추가 조사 대상이다. 조건이 존재한다는 사실만으로 장애 원인을 확정하지 않는다.
- 사람 입력·터미널 응답·크기 변경은 공통 클라이언트의 세션별 큐를 통과한다. 실제 Mac에서 키 이벤트 생성, 큐 제출, 네이티브 호출 완료, PTY 출력 중 어느 단계가 멈추는지 구분해야 한다.
- 기존 입력·렌더링 검사에는 실제 Vim 실행·편집·저장이 없었다. 긴 셸 명령 및 화면 파서 검사를 Vim 편집 검증으로 해석하면 안 된다.

## 이번 실행 결과

실제 프로덕션 UI와 Rust 웹 호스트, 실제 PTY, 실제 vi를 사용했다. 파일과 설정은 임시 디렉터리, SSH 서버는 폐기 가능한 루프백 OpenSSH다. Linux WebKit은 macOS 네이티브 WebKit과 같은 검증 환경이 아니다.

| 호스트 / 브라우저 | 셸 | 편집 시나리오 |
| --- | --- | --- |
| Linux / Chromium | 로컬 Bash | 5 통과 |
| Linux / WebKit | 로컬 Bash | 5 통과, ResizeObserver 경고 1회 |
| Linux / Chromium | 실제 루프백 SSH | 5 통과 |
| Linux / WebKit | 복합 명령으로 진입한 실제 루프백 SSH | 5 통과, ResizeObserver 경고 1회 |

각 실행은 비공유 편집, 편집 중 화면 재연결, 공유·제어 요청 후 사람 개입, 공유 상태의 편집 중 재연결, 100줄 파일의 마지막 행에서 창 크기 변경 후 편집을 검사한다. 일반 모드·삽입 모드 전환, 커서 이동·삭제·입력·저장과 저장 내용까지 확인한다. Vim 진입 후 포커스를 테스트가 강제로 복구하지 않는다.

`ResizeObserver loop completed with undelivered notifications.` 경고는 초기 엄격 실행에서 테스트를 실패시켰다. 편집·저장 검사는 그 실행에서도 통과했다. 정식 검사는 이 이미 알려진 경고를 별도 집계·출력하고 `runtime.json`에 보존하며 다른 브라우저 오류는 실패 처리한다. 경고가 무해하거나 이번 장애의 원인이라는 결론은 내리지 않았다.

## 남은 확인

1. 장애가 난 Mac의 실제 앱에서 일반 셸과 Vim 중 어디서 입력이 끊기는지 구분한다.
2. 내용 없이 포커스·렌더러 준비 상태·입력 요청 완료 여부·출력 진행 여부를 확인한다. 원시 키, 편집 버퍼, `.env` 내용은 수집하지 않는다.
3. 같은 Mac/SSH 경로에서 이전 릴리스와 비교하고 재현 조건을 고정한다. 사용자 작업을 종료하거나 미저장 파일을 버리지 않는다.
4. 재현을 실패하는 회귀 검사로 만든 뒤 수정하고 네이티브 재검증한다. 이번 Linux 결과를 Mac 수정 완료나 배포 승인으로 대신하지 않는다.
