## 구현한 동작

- **다른 탭의 작업을 놓치지 않기:** 다른 탭의 대기 요청과 살아 있는 연결의 최근 사용 터미널을
  하단에 표시한다. 탭을 열거나 옮겨도 사람의 선택은 유지한다. 안내를 클릭하면 세션 ID로
  현재 상태를 읽고 해당 탭으로 이동한다. 요청 ID가 이미 해결되었으면 그 사실을 안내한다.
  새 탭 등록과 이벤트 도착 순서가 달라도 상태 조회로 대기를 복구한다.
- **터미널 준비 부탁하기:** 연결 승인 후 접근 가능한 살아 있는 셸이 없으면 기존 attention
  도구로 준비를 요청한다. 사람은 `터미널 선택 / 새 터미널 / 나중에`를 선택한다.
  새 터미널은 비공개로 만들고 기존 공유 패널에서 참여자를 명시적으로 고른다.
  준비 요청은 연결별 하나이며 반복 요청은 합쳐지고, 나중에 처리한 뒤 10초간 재요청을 억제한다.
  요청 취소·연결 종료·공유 가능한 셸 준비 시 정리한다. 연결 승인 전에는 기존 admission 흐름이다.
- **상태와 안내:** Observe에서도 허용된 공유 탭으로 이동하고 사람의 확인을 요청할 수 있다.
  제어·입력은 계속 금지된다. 제어 만료 시간은 패널 안에서 서버 상태에 맞춰 표시한다.
  연결 단절과 셸 종료의 안내를 분리하고, 사람 입력의 제어 회수 범위가 해당 터미널임을 설명한다.
  알림은 제목의 요청 수와 네이티브 작업 표시줄/Dock attention을 사용하며 명령·출력은 담지 않는다.
  포커스 여부는 알림 전달에만 사용한다. 시스템 알림에서 개별 요청으로 이동하는 동작은 추가하지 않았다.
- **재접속:** 목록은 안정적인 세션 ID, 프로필 표시명, 프로세스 생존 여부를 제공한다.
  프로필명으로 원격 호스트·로그인 계정을 추측하지 않는다. 기존 셸을 명시적으로 다시 선택하고
  화면을 읽도록 도구 안내를 수정했다. 연결이 끊긴 마지막 명령은 자동 재실행하지 않는다.
  새 연결은 새 승인 대상이고, 이전에 선택된 공유·제어권·대기 작업을 이름으로 상속하지 않는다.
- **출력:** 창을 좁힐 때 UI는 줄을 재배치하지만 코어는 오른쪽 문자를 잘라내던 오류를 재현했다.
  코어는 셀 속성과 전각 문자 쌍을 보존하며 일반 화면을 재배치한다. 내부 기록은 UI와 같은 최대
  5,000행으로 제한하고 스냅샷은 현재 그리드만 반환한다. 대체 화면은 줄 재배치 없이 크기를 바꾼다.
  줄 끝 전각 문자의 연결 관계를 보존하고, UI에 공식 Unicode 11 애드온을 적용해 시험한 이모지 폭 차이를 수정했다.

연결 메타데이터와 준비 요청은 `ConnectionRegistry`, 사용 가능한 세션 판단은 `Hub`, 참여·제어·
명령 결정은 기존 `Session`이 소유한다. UI는 기존 공유 패널과 결정 카드를 재사용한다.
