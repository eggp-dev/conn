# SSH 입력과 승인 수정 결과

[English](ssh-input-review-results.md) · [테스트 재현 방법](browser-testing.md#ssh-input-cursor-and-approval-regression)

2026-09-22 · v0.8.4 (`06143d0`) 기준 v0.8.5 패치.

## 사용자 보고와 재현한 원인

사용자는 macOS에서 SSH 원격 셸을 사용하며, 긴 명령 이후 커서·입력 위치가 깨지고 **세션 허용**이 반응하지 않으며 위험 명령만 승인받는 자동 실행을 찾기 어렵다고 보고했다. 원하는 동작은 일반 명령 자동 실행, 위험 명령 승인이다.

- **승인:** SSH가 모든 명령을 개별 검토로 강제해 Autopilot에서도 세션 허용을 막았다. UI는 이유 없이 비활성화한 버튼을 표시했다.
- **입력·커서:** 설정은 모달로 바뀌었지만 예전 사이드 패널용 600픽셀 너비 축소가 남아 있었다. 설정을 열고 닫는 애니메이션 동안 실제 PTY가 반복해서 변경됐다. 실제 SSH의 긴 입력에서 화면 깨짐과 사용자 화면·코어 그리드 불일치를 재현했다.
- **긴 승인 내용:** 약 5,000자 명령이 승인 버튼을 화면 아래로 밀어냈다. 공통 카드에서 내용만 스크롤하고 동작 버튼은 유지하도록 수정했다.

## 변경 후 동작

POSIX SSH는 호스트의 cwd·홈·파일 경로를 검사하지 않고 기존 명령 정책을 적용한다. Autopilot에서 일반 명령은 실행하고 확인 규칙은 승인을 요청하며 금지 규칙은 계속 차단한다. 세션 허용은 해당 확인 규칙 이름에만 적용하고 UI에 즉시 알린다. Co-pilot, 연결 승인, 공유, 제어권 부여는 별도 책임을 유지한다.

SSH 프로필, 직접 실행한 SSH, Bash/Zsh 통합이 식별한 단일 SSH 명령에 적용한다. 해당 SSH 종료가 확인되면 로컬 분석으로 돌아간다. SSH 실행 상태 추적이 끊기면 개별 검토로 전환한다. 다른 원격 백엔드·비POSIX 셸·식별하지 못한 프로그램은 명령별 검토를 유지하고 UI에서 이유를 설명한다.

모달 설정을 열어도 뒤쪽 PTY 크기를 바꾸지 않는다. 실제 창과 협업 패널 크기 변경은 그대로 반영한다. 셸 교체, 원격 훅, 별도 실행 경로는 추가하지 않았다.

## 검증과 한계

- 기본 Rust 테스트 258개 통과. 기존 선택 실행 SSH 테스트는 이 수치에서 제외했다.
- 별도 실제 OpenSSH 인증·공유 테스트 통과. 원격 일반 명령 실행과 권한 상승 명령의 승인 대기를 확인했고, 권한 상승 명령은 실행하지 않았다. 비공유 인증정보는 공유 데이터에 남지 않았다.
- 프런트엔드 48개, 데스크톱 프런트엔드 빌드, 코어/xterm 화면·커서 비교 85회, 사이트 빌드, 저장소·문서 검사 통과.
- 공통 UI·실제 Rust·루프백 SSH 하네스에서 240~7,000자 입력, 한글·이모지, 반복 설정 열기·닫기, 작은 창의 긴 명령 승인, 세션 허용 범위, 사람의 커서 이동·중간 삽입·제어권 회수, 원래 로컬 셸 복귀를 검사했다.
- 기존 협업 맥락 하네스는 탭·알림·공유·재접속·셸 준비 12단계를 검증한다.

위 브라우저 검증 환경은 Linux Chromium과 UTF-8 원격 Bash다. 아래 macOS 네이티브 검증은 별도 실행 결과다. 사용자 증상의 모든 원인이 해결됐다고 단정하지 않으며, 배포 파일 검증은 별도로 기록한다.

## macOS 네이티브 후속 검증

2026-09-22, `codex/terminal-input-review`의 `ed57aac936bec98e26f0a69ac06241cef36c5834`를 Apple Silicon Mac에서 확인했다. 작업 폴더를 새로 복제했고 기존 로컬 변경은 없었다. [해당 커밋의 CI](https://github.com/eggp-dev/conn/actions/runs/35691004269)는 Linux·macOS·Windows의 Rust/데스크톱, 문서·프런트엔드, 협업 브라우저와 필수 검사 모두 성공했다. PR #63은 Draft 상태였다.

### 실행 환경과 증거 범위

- macOS 27.0 (`26A428`), arm64, Node.js 24.13.0, Rust 1.95.0. 루트 `npm ci` 완료.
- `frontends/tauri`에서 `npm run tauri dev`로 네이티브 실행을 확인했다. UI 조작 도구가 번들 없는 개발 프로세스를 선택하지 못해, 최종 조작은 같은 소스의 `npm run tauri build -- --debug --bundles app --config <임시 설정>`으로 만든 ad-hoc 서명 디버그 번들에서 진행했다. 임시로 감싼 개발 바이너리는 최종 검증 대상이 아니다.
- 테스트용 앱 이름·식별자, `CONN_CONFIG_DIR`, `CONN_SOCKET`을 분리하고 실행 바이너리 경로와 소켓 소유 PID를 확인했다. WebKit의 실제 `tauri://localhost` UI와 Tauri IPC를 사용했으며 브라우저 하네스로 대체하지 않았다.
- 별도 루프백 OpenSSH 서버, 임시 키·고정 호스트 키, 실제 `/bin/bash --noprofile --norc -i`, `en_US.UTF-8`, `xterm-256color`. SSH 명령은 Conn의 기존 로컬 PTY에서 입력했다. 실제 삭제 대상은 이번 실행에서 만든 임시 파일 두 개뿐이다.
- Mac에서 Rust 258개 통과·기존 선택 실행 SSH 테스트 1개 제외, 프런트엔드 48개 통과, 프런트엔드·네이티브 디버그 번들 빌드 통과, 코어/xterm 비교 85회 통과. 마지막 비교는 자동 파서 검사이며 네이티브 DOM 전체 비교 횟수가 아니다.

### 직접 확인한 동작

| 항목 | 결과 |
| --- | --- |
| 일반 명령 자동 실행 | 오른쪽 위 제어 상태에서 Autopilot을 선택했다. 연결 허용과 제어권 승인은 각각 별도로 진행했고 원격 `printf`, 임시 파일 `touch`는 명령 승인 없이 `executed`를 반환했다. |
| 긴 영문 입력과 설정 | 1,521자·7,029자 입력에서 설정 열기 전후 PTY 크기, 화면, 커서, 출력 순번이 동일했다. 반복 열기·닫기 후에도 입력을 유지했고 7,000자 본문 출력과 프롬프트 복귀를 확인했다. 설정을 연 상태에서도 같은 에이전트가 실행할 수 있었다. |
| 한글·이모지와 실제 창 크기 | `한글/경로/🙂/` 65회 반복을 붙여넣었다. 설정 열기·닫기와 1120×720 → 757×433 → 원래 크기 변경을 확인했다. 137열에서 90열로 바뀐 화면의 커서 위치를 코어 스냅샷과 대조했다. |
| 사람의 편집·제어권 회수 | 영문·한글 긴 명령에서 좌우 이동, 중간 삽입, Backspace, Enter를 조작해 `EDITEND>`·`수정END>` 출력을 확인했다. 에이전트 제어 중 첫 방향키 입력은 `human_input`으로 제어권을 회수했고 이후 에이전트 쓰기는 `not_controller`로 거절됐다. |
| 긴 승인 카드 | 5,109자 삭제 명령은 실행되지 않고 `delete files` 승인 대기가 됐다. 757×433 창에서 내용은 카드 안에서 스크롤되고 승인·거부·세션 허용 버튼이 보였다. **세션 허용** 클릭 후 `granted`와 임시 파일 삭제를 확인했다. |
| 허용 범위와 철회 | 다음 임시 파일 삭제는 승인 없이 실행됐다. `recursive delete`와 `privilege escalation`은 계속 승인 대기했고 UI에서 거부했다. 설정의 허용 목록에는 `delete files`만 표시됐다. 이를 철회하자 같은 규칙도 다시 승인 대기가 됐다. 한국어 UI에서 개별 승인도 확인했다. |
| 금지 규칙 | 정책 테스트의 루트 삭제 명령은 `deny`였다. 실제 에이전트 Enter 경로는 위험 문자열을 인자로만 담은 무해한 `printf '%s\n' 'rm -rf / '`로 검사해 `delete root`·`denied`와 정책 차단 타임라인을 확인했다. 실제 루트 삭제 명령은 실행 경로에 제출하지 않았다. |
| 승인 중 사람 입력 | Ctrl-C가 대기 명령을 실행하지 않고 `denied (human_input)`으로 정리하며 제어권을 회수했다. 이후 사람의 명령으로 동일 원격 Bash PID를 확인했다. |
| 원래 셸 복귀 | SSH 종료 후 처음의 로컬 Bash PID와 동일한 PID를 확인했다. 세션 화면 식별자도 유지됐다. |

네이티브 화면은 접근성 트리와 창 캡처로 확인하고, 선택한 화면·커서 위치는 에이전트 스냅샷과 대조했다. 모든 네이티브 행을 자동 비교한 검증은 아니다. 소켓 응답, 스냅샷, 감사 기록과 빌드 로그는 Mac의 임시 검증 폴더에 보관했으며 개인 경로·키·원시 로그·캡처는 저장소에 추가하지 않았다. 추가 제품 코드 변경은 하지 않았다.

### 남은 확인과 관찰

- **실제 키보드 한글 IME 조합은 미검증이다.** 자동 키 입력에서는 입력란의 `한글`과 PTY의 초성이 달랐다. 임시 WebKit 이벤트 추적에는 `compositionstart/update/end`가 없고 `isComposing=false`인 `insertText`/`insertReplacementText`와 키 이벤트가 기록됐다. 이 전달 방식으로 실제 키보드 조합의 성공·실패를 판정할 수 없어 제품 우회 코드를 넣지 않았다. 한글·이모지 붙여넣기와 커서 편집 통과를 IME 통과로 확대하지 않는다. 진단용 추적은 제거했다.
- WebKit 검사기에 크기·패널 변경 뒤 `ResizeObserver loop completed with undelivered notifications` 메시지가 누적돼 있었다. 확인한 화면·커서·편집 단계에서 지속되는 불일치는 재현되지 않았으나, 이를 오류 없는 콘솔 실행으로 기록하지 않는다.
- 사용자의 실제 SSH 서버·셸 설정, 비UTF-8 줄 편집기, 다른 macOS 버전, 서명·공증된 배포 앱의 설치·업데이트는 별도 확인이 필요하다. 이 네이티브 검증 당시 버전은 0.8.4, 변경 내역은 Unreleased였다. 해당 검증 자체는 머지·태그·릴리스가 아니다.
