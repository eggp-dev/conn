# 제어권 모델: 회수 가능한 임대

상태: **구현됨** · 2026-09-19. 4장과 5장의 "구현" 항목은 코드와 테스트에 들어가 있고,
"남긴 것"은 의도적으로 미룬 항목입니다. 영문판은 아직 없습니다.

## 1. 풀려는 문제

사람 한 명과 에이전트 여럿이 같은 셸 하나를 씁니다. 키 입력이 섞이면 멀티스레드의 데이터
레이스와 같은 일이 생깁니다. 반쯤 친 명령에 다른 주체의 글자가 끼어들고, 누가 무엇을 실행했는지
알 수 없게 됩니다. Conn의 제어권은 이 문제를 푸는 **락**입니다.

다만 일반 mutex와 두 가지가 다릅니다. 사람은 언제든 빼앗을 수 있어야 하고, 락을 놓아도 셸의
상태(입력 줄, 실행 중인 프로세스)는 되돌아가지 않습니다. 그래서 이름을 mutex가 아니라
**회수 가능한 임대(revocable lease)** 로 합니다.

## 2. 비유와 실제 구현

| 개념 | Conn |
| --- | --- |
| 프로세스 | 실행 중인 Conn 앱 |
| 스레드 | 사람이 수락한 에이전트 연결 하나 (사람은 특권 스레드) |
| 공유 메모리 | 일반 탭의 터미널 그리드 |
| 별도 주소 공간 | 외부 기원 private 세션, 공유를 중단한 탭 |
| 락 | 탭마다 하나인 입력 제어권 (`Authority`, `Controller::Human \| Agent(Lease)`) |
| `try_lock` | `request_control`: 남이 보유 중이면 `busy`를 즉시 반환, 대기하지 않음 |
| 임대 만료 | TTL. 쓰기가 성공할 때마다 갱신 |
| 보유자 사망 감지 | 연결 EOF/쓰기 실패 → 임대 회수와 대기 작업 취소 |
| 세대 토큰 | `lease#N`, `participation_generation`, `surface_generation` |
| 락 없는 읽기 | 스냅샷: revision이 붙은 그리드. 읽기는 아무것도 막지 않음 |
| 낙관적 검사 | 자동완성 수락 시 `surfaceId + generation + revision` 대조 |

## 3. 불변식

테스트로 고정해야 하는 규칙입니다. 괄호 안은 현재 근거 테스트입니다.

1. **단일 작성자.** 한 탭에서 어느 순간에도 PTY에 쓸 수 있는 주체는 하나입니다.
2. **사람 선점.** 사람의 입력은 항상 즉시 제어권을 회수합니다. 에이전트끼리는 선점하지 못합니다.
   사람이 항상 끼어들 수 있으므로 교착은 성립하지 않습니다.
3. **죽은 보유자는 아무것도 실행하지 못합니다.** 연결이 끊기면 임대, 승인 대기, Co-pilot 제안,
   Grace 예약이 모두 취소됩니다. 끊긴 뒤에 도착한 쓰기 요청은 `connection_closing`으로 거절됩니다.
   (`lifecycle_audit.rs`)
4. **오래된 토큰은 거절됩니다.** 공유 전환·참여자 변경 이전에 만들어진 응답과 이벤트는 전달 직전에
   세대를 다시 확인해 버립니다. (`shared_surface.rs`)
5. **읽기는 락과 무관합니다.** 참여 권한이 있는 연결은 제어권 없이도 스냅샷을 읽습니다.
   창 포커스, 보이는 탭, 최소화 여부는 접근 조건이 아닙니다. (`attention.rs`)
6. **볼 수 없는 것은 제출할 수 없습니다.** 커서 줄에 스냅샷이 가린 글자가 있으면 에이전트의
   ENTER는 거절됩니다. (`shared_surface.rs`)
7. **바인딩은 따라가지 않습니다.** 에이전트는 자기 세션에 묶여 있고, 이동은 명시적 `switch_tab`뿐이며
   목적지의 참여 권한을 매번 다시 확인합니다. (`lifecycle_audit.rs`, `mcp_lifecycle.rs`)
8. **수락 전에는 아무것도 없습니다.** 대기 중이거나 거부된 연결은 어떤 세션도 알 수 없습니다.
   (`admission.rs`)
9. **참여와 제어는 별개입니다.** 참여 권한은 "누가 스레드인가", 임대는 "지금 누가 쓰는가"입니다.
   임대를 얻어도 모드·정책·승인은 그대로 적용됩니다.

## 4. 신뢰 경계는 탭이 아니라 연결

일반 탭은 `shared: true, participants: None`으로 시작해 수락된 모든 연결에 열려 있습니다.
예전에는 "사람이 보고 있는 탭만"이라는 조건이 이를 좁혔지만 그 조건은 폐기되었습니다.
그래서 명시적 동의 지점을 **연결 수락**으로 옮겼습니다. 스레드를 만들 때 한 번 허락하고,
그 뒤에는 공유 메모리를 함께 쓰는 모델입니다.

구현된 흐름:

1. 새 연결이 `hello`를 보내면 **대기** 상태가 됩니다. 응답은 `admission: "pending"`이고 세션,
   모드, 주의 상태는 모두 비어 있습니다. 공유 대화상자의 후보에도 나타나지 않습니다.
2. 소유자 창에 "`<agentId>` 참여를 요청합니다" 카드가 뜹니다. **허용 / 거부** 두 개뿐입니다.
3. 대기 중 탐색 호출은 즉시 `admission_pending`을 받습니다. 그 밖의 호출은 최대 25초 동안 결정을
   기다리므로, 사람이 허용을 누르면 에이전트의 첫 호출이 그대로 성공합니다.
4. 허용된 연결은 일반 탭 전체에 참여합니다. 쓰기는 여전히 임대가 필요합니다.
5. 거부는 그 연결에 대해 최종입니다. 같은 이름으로 다시 접속해도 아무것도 물려받지 않습니다.
6. 탭별 선택과 공유 중단은 고급 설정으로 남습니다. 외부 기원 private 세션은 그대로 보이지 않습니다.

결정한 것과 이유:

- **토큰·이름으로 기억하지 않습니다.** 소켓은 같은 OS 사용자만 접근할 수 있으므로 이 장치는
  악성코드 방어가 아니라 **동의 경계**입니다. 막으려는 상황은 "설정해 둔 클라이언트의 다른 세션이
  말없이 내 터미널 전체를 읽는 것"입니다. 설정 파일에 든 토큰으로 자동 허용하면 바로 그 상황이
  통과합니다. 표시 이름은 누구나 사칭할 수 있습니다. 그래서 결정은 살아 있는 연결 하나에만 묶입니다.
- **기본값은 묻기, 클릭 한 번.** MCP 연결은 에이전트 세션 동안 유지되므로 세션당 한 번입니다.
  첫 사용에서 "사람이 허락해야 들어온다"가 눈에 보이는 것은 제품 가치 그 자체입니다.
- **끌 수 있습니다.** 설정 → 에이전트 → "새 에이전트가 참여하기 전에 묻기". `app.json`의
  `admission: "allow"`로 저장되며 탭 기본값을 저장해도 유지됩니다.
- **코어 임베더의 기본은 허용입니다.** 정책은 호스트가 정합니다. 데스크톱 앱이 `Ask`를 켭니다.
- **protocol v2 안에서 추가했습니다.** `hello` 응답 필드와 오류 코드 두 개가 늘었을 뿐입니다.

근거 테스트: `core/tests/admission.rs`, `frontend/tests/admission_harness.rs`,
`cli/tests/mcp_lifecycle.rs::pending_admission_keeps_one_tool_that_succeeds_after_allow`.

## 5. 임대 규칙

구현:

- **임대는 탭에 속합니다.** `switch_tab`과 `open_tab`으로 떠나면 그 탭의 임대를 즉시 반납하고,
  그 연결의 승인 대기·제안·Grace 예약·제어 요청을 취소합니다. 한 연결이 여러 탭을 쥐는 일이 없어
  에이전트 간 순환 대기가 원천적으로 생기지 않습니다. (`admission.rs::moving_to_another_tab…`)
- **한 연결은 한 번에 한 탭만 쥡니다.** 요청은 허용된 `session`을 이름으로 지정할 수 있으므로 바인딩만으로는
  이 규칙이 지켜지지 않습니다(macOS 검증에서 발견). 다른 세션에 `request_control`을 보내면 나머지 세션에서
  쥐고 있던 것을 모두 반납합니다. 이름으로 읽는 것은 아무 영향이 없습니다.
  (`admission.rs::naming_a_session_explicitly…`)
- **출발 탭 마스크는 유효합니다.** 출발 탭이 살아 있고 참여 중이며 소유자 마스크에 `switch_tab`이
  없으면 이동은 `masked`로 거절되고 도구 목록에도 나오지 않습니다. 출발 탭이 닫혔거나, 비공개가
  되었거나, 종료되었거나, 참여에서 빠졌다면 복구를 막지 않습니다. (`admission.rs::an_owner_mask…`)
- **보지 않는 탭의 Grace는 문을 두드립니다.** Grace는 사람이 거부할 기회이므로, 사람이 보고 있지
  않은 탭에 예약되면 주의 요청을 함께 띄웁니다. (`attention.rs::grace_in_a_tab…`)

남긴 것:

- **대기열.** 지금처럼 `busy`를 즉시 반환합니다. 에이전트 여럿이 한 탭을 두고 경쟁하는 사용이
  실제로 나타나면 `control_requests`를 선착순 대기열로 확장합니다.
- **사람을 기다리는 동안의 보유 상한.** 승인 대기 중에는 `renew()`가 임대를 연장합니다. 사람은
  언제든 회수할 수 있으므로 안전 문제는 아니고, 굶주림이 관찰되면 상한을 둡니다.
- **안전한 인계 지점(`input_pending`).** TUI의 입력 상태 모델은 사용자 결정으로 보류 중입니다.

## 6. 용어

문서와 UI에서는 "mutex" 대신 **제어권 / 임대(lease)** 를 씁니다. mutex라고 쓰면 "보유자가 놓을 때까지
아무도 빼앗지 못한다"로 읽히는데, Conn의 핵심 약속은 그 반대입니다.
