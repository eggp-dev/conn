AI 에이전트와 같은 셸에서 일하세요. 직접 고치고, 바뀐 화면에서 이어가게 하세요.

## 짧은 소개 글

> 에이전트가 작업할 폴더를 골랐는데, 내가 원한 곳이 아니었습니다. 키보드를 잡고 폴더를 바꾼 뒤 말했습니다. “터미널을 읽고 여기서 이어가.”
>
> Conn은 이런 협업을 위한 터미널입니다. 대화는 쓰던 에이전트에서 하고, 작업은 같은 셸에서 함께 봅니다. 내가 직접 고친 뒤에는 에이전트가 달라진 화면을 읽고 이어갑니다.
>
> Apple Silicon macOS·Windows x64·Ubuntu x64용 오픈소스 프리뷰입니다. Codex, Claude Code, Cursor, GitHub Copilot의 연결 설정을 지원합니다. 작은 로컬 예제를 해보고 제어권을 주고받을 때 헷갈린 부분을 알려주세요.
>
> https://github.com/eggp-dev/conn

짧은 경로 보정 영상을 함께 사용합니다. **실제 Codex와 Conn을 사용했고, 준비된 시나리오에서 사람 역할은 자동화했으며 대기 시간은 편집했다**는 설명을 가까이 둡니다.

## 개발자 커뮤니티용 소개

**제목:** 에이전트가 고른 작업 폴더를 내가 직접 고쳤다 — 같은 터미널에서 협업하는 Conn

> 에이전트가 터미널 작업을 할 때, 옆에서 보고 있다가 내가 직접 고치고 다시 맡기고 싶어 Conn을 만들었습니다.
>
> 최근 원격 환경을 준비하던 중 에이전트가 내가 원하지 않은 위치에 프로젝트를 만들려고 했습니다. Conn에서 직접 키보드를 잡고 경로를 바꾼 뒤, 현재 화면을 다시 읽고 이어가라고 했습니다. 에이전트는 수정된 위치에서 작업을 재개했습니다.
>
> Conn은 Rust/Tauri 기반 터미널이고, MCP나 CLI로 기존 에이전트에 연결합니다. 대화와 모델 계정은 쓰던 클라이언트에 그대로 둡니다. 직접 입력하면 터미널 제어권을 되찾고, 명령과 협업 결정은 타임라인에서 함께 볼 수 있습니다.
>
> 아직 프리뷰이며 OS 샌드박스는 아닙니다. 제어권 회수는 이후 에이전트 입력을 막는 동작이고, 이미 실행 중인 프로세스를 중단하지는 않습니다. 일반 세션에서 화면 조회가 허용된 에이전트는 보이는 터미널 출력을 읽을 수 있습니다.
>
> README에 설치 파일과 작은 로컬 체험을 준비했습니다. 영상은 실제 Codex 세션으로 협업을 재현했으며, 사람 역할은 자동화하고 대기 시간을 편집했습니다. 설명 없이 첫 연결과 제어 전환을 이해할 수 있는지 피드백을 듣고 싶습니다.
>
> 에이전트 작업 도중 직접 키보드를 잡고 싶었던 순간은 언제였나요?
>
> https://github.com/eggp-dev/conn

게시할 커뮤니티의 규칙을 먼저 확인하고, 제작자가 직접 소개하는 글임을 밝힙니다. 같은 홍보글을 여러 곳에 무차별 반복하거나 투표·댓글을 조직하지 않습니다. 영어 공개용 제목과 Show HN 초안은 [영문 자료](launch-kit.md)에 있습니다.

## 프로젝트 소식용 문구

> **조금 고쳤다고, 처음부터 다시 할 필요는 없으니까.** 새로운 Conn 안내 영상은 에이전트가 작업을 준비하고, 사람이 목적지를 바꾸고, 에이전트가 수정된 화면을 읽고 이어가는 모습을 보여줍니다. 영·한 README도 쓰던 에이전트로 직접 해볼 수 있는 작은 로컬 예제에 맞춰 정리했습니다.
>
> 데스크톱 프리뷰를 설치하고 설정 → 에이전트에서 클라이언트를 연결해보세요. 앱 배포 파일은 기존 v0.6.0이며, 이번 변경은 협업 안내와 문서입니다.

최종 영상 검토 후 사용할 문구입니다. 만들지 않은 새 앱 버전을 발표하는 내용이 아닙니다.

## 사례 글의 시작

**제목:** 경로는 내가 고쳤어. 여기서 이어가.

> 원격 환경을 세팅하던 중 에이전트가 고른 작업 위치가 내 의도와 달랐습니다. 채팅으로 다른 경로를 설명할 수도 있었습니다. 대신 공유 터미널에 직접 입력해 제어권을 가져오고, 셸을 원하는 곳에 놓았습니다. 그리고 현재 터미널을 다시 읽어달라고 했습니다.
>
> 에이전트는 바뀐 상태를 확인하고 이어갔습니다. 편했던 것은 명령 자체가 아니라, 내 수정 내용을 다시 길게 설명하지 않고 작업에 직접 참여할 수 있었다는 점입니다.

이후 화면 세 장으로 설명합니다. 변경 전 → 직접 보정 → 결과 확인 순서입니다. 실제 계정·호스트·개인 경로·인증 화면을 공개하는 대신 임시 환경에서 재현합니다. 원격 실험에서 성공한 부분과 남은 문제는 구분합니다. [당시 관찰 기록](collaboration-backlog/2026-09-16-remote-codex.md)은 사례의 근거이며 모든 환경의 호환성을 보장하지 않습니다.

## 자주 나올 질문에 대한 답변 초안

**“기존 터미널이나 에이전트 도구를 쓰면 안 되나요?”**

> 지금 도구가 작업 방식에 맞는다면 그대로 사용해도 됩니다. Conn이 집중하는 것은 쓰던 에이전트와 같은 셸에서 일하면서 내가 작업 상태를 직접 바꾸고, 에이전트가 다시 읽어 이어가는 경험입니다. 작은 예제로 내 작업에 도움이 되는지 확인해보세요.

**“에이전트에게 터미널을 맡겨도 안전한가요?”**

> Conn의 검토·제어 회수 기능은 신뢰하는 에이전트와 협업하기 위한 장치이며 OS 격리가 아닙니다. 명령은 사용자 계정 권한으로 실행되고, 허용된 화면 조회에는 보이는 출력이 포함될 수 있습니다. 신뢰 모델에 범위를 설명해두었습니다. 임시 예제로 먼저 체험해보세요.

**“제가 쓰는 클라이언트도 되나요?”**

> Codex 데스크톱·CLI·IDE의 로컬 작업, Claude Code, Cursor, GitHub Copilot의 연결 설정을 제공합니다. 별도 ChatGPT 앱이나 클라우드 작업을 연결하는 기능은 아닙니다. 대표 영상은 Ubuntu에서 Codex를 사용했으며, 모든 클라이언트·OS 조합을 검증했다는 뜻은 아닙니다. 설정이 안 되면 클라이언트·버전·OS를 함께 알려주세요.

**“해봤는데 막혔어요.”**

> 설치·연결·제어 승인·직접 개입·재개 중 어느 단계였나요? 공개 가능한 작은 예제와 Conn·클라이언트 버전, OS, 셸이 도움이 됩니다. 화면과 요청 원문은 공유 전에 검토해주세요. 인증정보나 터미널 전체 덤프는 필요하지 않습니다.

## 5명 첫 사용 검토

각 참가자의 동의를 받아 다음 순서로 진행합니다.

1. 짧은 영상을 설명 없이 보여주고 “Conn으로 무엇을 할 수 있나요?”라고 묻습니다.
2. README를 주고 쓰던 에이전트를 연결하도록 합니다.
3. 코칭 없이 [첫 협업](first-collaboration.ko.md)을 따라 하도록 합니다.
4. “직접 입력하면 무엇이 달라졌나요? 실행 중인 명령도 멈출 거라 예상했나요?”라고 묻습니다.
5. 일주일 뒤 실제 작업에서 다시 썼는지, 어떤 일이 있었는지 물어봅니다.

단계·소요 시간·도움 여부·자발적 의견만 기록합니다. 터미널 내용이나 인증정보를 수집하지 않습니다. 직접 완료한 것과 이해했다고 답한 것은 구분합니다. 소수 사용성 점검이며 성능 벤치마크가 아닙니다.
