# Conn 제품 백로그

[English](product-backlog.md) · 한국어 · [기존 리팩터링 계획](collaboration-refactor-plan.ko.md)

## 2026-09-21 — 실제 원격 셸 협업 피드백

상태: v0.8.4 필수 협업 범위 구현 및 공통 하네스 검증 완료. [구현 범위와 남은 검증](collaboration-context-results.ko.md)을 참고한다.
아래 우선순위는 출시 일정이나 모든 완료 기준 충족을 뜻하지 않는다.
제품 목표는 **500+ GitHub stars**로 상향되었다. 기능 수보다 첫 협업 성공, 작업 맥락의 명확성,
반복 사용과 신뢰를 개선하는 데 집중한다. 이 문서는 게시·홍보 실행을 승인하는 문서가 아니다.

### 핵심 가치와 근거

> 사용자가 실제 터미널에서 에이전트의 작업 위치와 흐름을 눈으로 따라가며, 필요할 때 같은 자리에서 개입할 수 있다.

| 근거 | 보고된 내용 | 증거의 한계 |
|---|---|---|
| F01 · Copilot 작업 후기 | 실제 SSH 셸에서 화면 조회 → 제어 요청 → 명령 승인 → 읽기 전용 명령 실행 → 결과 확인 → 제어 반환 성공 | 사용자에게 전달받은 에이전트의 보고이며 이번 문서 작업에서 독립 재검증하지 않음 |
| F02 · 비교·사용성 평가 | 반복 배포·운영에서 요청·승인·결과가 이어져 편리하고, 절차가 복잡하지 않다는 평가. iTerm2 MCP보다 해당 작업에 적합하다는 의견 | 통제된 경쟁 제품 비교나 독립 사용자 연구가 아닌 에이전트의 평가 |
| F03 · 사용자 직접 관찰 | 서로 다른 계정으로 로그인된 셸 간 이동과 이동 안내를 확인. 실제 원격 셸에서 어디를 작업하는지 시각적으로 추적하는 경험을 긍정적으로 평가 | 셸 이동 관찰이며 계정·권한 경계 전체의 검증은 아님 |
| F04 · 후속 작업 후기 | 명령 의도 확인, 사람 입력 시 제어 회수, 승인 흐름에서 신뢰를 느낌. 재접속·lease·반복 실행·긴 출력에는 불편을 보고 | 주관적 신뢰를 운영 안전성 보장이나 우회 불가능성으로 확대하지 않음 |

기존의 사람이 경로를 바로잡고 에이전트가 이어가는 사례는 [협업 이야기](collaboration-story.ko.md)에 있다.
실제 주소·계정·명령 원문·인증 응답은 이 백로그에 보관하지 않는다. 재현에는 합성 데이터를 사용한다.

### UX-01 · 긴 출력의 표시 정확성

- 2026-09-22: **v0.8.5 이후에도 미해결**. 업데이트·재시작 뒤에도 고정 창에서 알림·승인 바가
  움직일 때 가로·세로 영역 제한과 입력 위치 깨짐이 보고됐다. 크기 변경·출력 순서 결함을 재현하고
  후속 수정했으나 아직 미배포이며 실제 설치된 네이티브·원격 환경은 미검증이다.
  [터미널 크기 후속 조사](ssh-input-review-results.ko.md#v085-이후-터미널-크기-후속-조사--미배포)를 참고한다.
- 문제: 긴 경로와 OAuth 응답이 줄바꿈 때문에 깨져 보인다는 보고.
- 범위: 실제 출력, 터미널 그리드, 렌더링, 에이전트 스냅샷을 비교해 원인을 분리한다.
- 완료 기준: 합성 긴 경로·URL·토큰 형태 문자열, 한글/유니코드, 붙여넣기, 창 크기 변경,
  로컬/SSH 출력에서 문자 유실·중복·순서 오류를 검증한다. 의도적인 소프트 랩은 오류와 구분한다.
  숨김 입력을 수집하거나 가시성 규칙을 완화해 해결하지 않는다.

### UX-02 · 어느 셸인지 명확하게

- 문제: 셸 간 이동은 자연스럽지만 서로 다른 계정·호스트의 작업 대상을 더 분명히 보여줄 필요가 있다.
- 범위: 탭 이름, 이동 안내, 요청 카드의 대상 표현을 공통화한다.
- 완료 기준: 서로 다른 두 계정/호스트의 셸을 오갈 때 요청과 결과의 대상을 구분할 수 있다.
  호스트·계정은 확인 가능한 정보만 표시하며 알 수 없을 때 추측하지 않는다.
  탭 이름 변경·종료·재연결에도 안정적인 세션 식별자를 따른다. 공유 화면을 불필요하게 복잡하게 만들지 않는다.

### UX-03 · 대기 상태와 lease 안내

- 문제: 연결 승인, 제어 승인, 명령 검토, lease 만료가 사용자와 에이전트에게 번거롭거나 불명확하다.
- 범위: 각 상태의 이유, 기다리는 주체, 다음 행동과 제어권 만료 정보를 일관되게 표현한다.
- 완료 기준: 만료 전후·갱신·거절·취소·사람 입력으로 회수되는 경우를 검증한다.
  표시 시간은 서버 상태와 일치하고 오래된 승인 UI가 되살아나지 않는다.
  대기 중인 사용자에게 필요한 행동을 안내하며 상시 카운트다운 등 시각적 소음은 피한다.
  기본 TTL 변경이나 관찰만으로 자동 갱신하는 정책은 별도 결정한다.

### UX-04 · 준비 요청과 알림

- 문제: 접근 가능한 탭이 없으면 에이전트가 터미널 준비를 부탁하기 어렵다. 다른 셸에서의 요청도 놓치기 쉽다.
- 범위: 기존 attention의 세션 없는 요청 가능 여부를 확인하고 확장한다.
  연결 승인 전에는 기존 admission 카드, 승인 후 접근 가능한 셸이 없으면 터미널 선택 요청을 사용한다.
- 완료 기준: 탭 없음·모두 비공개·다른 탭·앱 비활성 상태에서 요청의 대상을 찾아갈 수 있다.
  `터미널 선택 / 새 터미널 / 나중에` 또는 이에 준하는 간결한 행동을 제공한다.
  클릭은 해당 셸·요청으로 이동할 뿐 자동 공유·승인·제어 획득을 하지 않는다.
  이동은 조용한 화면 내 안내, 사용자 행동이 필요한 대기는 더 명확한 알림으로 구분한다.
  완료·막힘 알림은 확인 가능한 상태 또는 에이전트 보고로 구분하며 입력 전달을 성공으로 오인하지 않는다.
  중복·폭주 요청을 합치고 해결·취소된 요청을 정리한다. 시스템 알림에 명령·출력·인증정보를 기본 노출하지 않는다.
  창을 강제로 활성화하거나 사용자의 입력 포커스를 빼앗지 않는다.

### UX-05 · 기존 셸 재발견과 복구

- 문제: 연결이 끊긴 뒤 기존 원격 셸을 다시 찾는 과정이 번거롭다.
- 범위: 에이전트 연결 단절, SSH 단절, 셸 종료를 구분하고 살아 있는 세션을 재발견하게 한다.
- 완료 기준: 같은 세션이 살아 있으면 계정·작업 상태를 유지한 채 다시 선택할 수 있다.
  종료된 셸을 새로 열었을 때 복구된 셸처럼 표현하지 않는다.
  새 연결 ID에 이전의 공유 선택·제어권·미해결 승인을 자동 상속하지 않는다.
  재인증은 사용자에게 맡기며 자격 증명을 저장하거나 재주입하지 않는다.

### UX-06 · Observe 사용 흐름

- 문제: 읽기 전용 관찰 모드를 요청받았으나 기존 Observe가 있다.
- 범위: 기능 추가 전, 발견성 문제인지 실제 접근 제한 문제인지 사용 시나리오로 확인한다.
- 완료 기준: 공유된 셸을 읽고 Observe의 제한을 이해할 수 있다. 관찰만으로 비공개 셸 접근이나
  제어·입력 권한을 얻지 않는다. 필요한 경우 기존 설정·안내를 개선하고 모드를 중복 추가하지 않는다.

### UX-08 · 다중 탭 협업 맥락

- 재현: 사람이 1번 탭을 보는 동안 에이전트가 2·3번 탭을 열고 작업하면 요청 카드는 해당 탭에만
  나타나고, 알림 클릭은 사람이 보고 있던 탭의 패널을 열었다. 백그라운드 탭 사이 이동도 놓치기 쉬웠다.
- 범위: 다른 탭의 대기 요청과 살아 있는 연결의 최근 작업 대상을 계속 표시하고, 알림을 안정적인
  세션·요청 ID에 연결한다. 새 탭 등록 중 발생한 요청도 상태 조회로 복구한다.
- 완료 기준: 사용자가 선택한 탭은 유지되고, 안내를 클릭하면 정확한 셸과 요청으로 이동한다.
  닫힌 탭·해결된 요청·같은 이름의 새 연결을 구분한다. 이동 자체는 승인·공유·제어 획득을 하지 않는다.
  사람 입력에 의한 회수가 현재 터미널에만 적용된다는 점을 이해할 수 있다.

### UX-07 · 명령 묶음 실행

- 문제: 한 줄씩 요청·입력·실행하는 과정이 반복 작업을 방해한다.
- 범위: 사용자가 전체 실행 내용을 검토할 수 있는 제한된 묶음 실행을 먼저 설계한다.
- 완료 기준: 명령별 정책 평가, 승인 범위, 오류 시 정지/계속, 부분 완료 표시를 정의한다.
  사람 입력·제어 회수·공유 중단·연결 단절 시 남은 실행이 취소되는지 검증한다.
  인증/TUI 입력을 일반 명령 묶음으로 취급하지 않는다. 읽기 전용 또는 안전한 명령이라는
  에이전트의 주장만으로 정책을 생략하지 않는다. 기존 복합 명령 지원과 중복되는지도 확인한다.

### SEC-01 · 민감 정보 마스킹 조사

- 문제: curl의 Cookie·토큰 등이 보이는 출력이나 기록에 남을 수 있다는 우려와 자동 마스킹 요청.
- 범위: 공통 화면의 선택적 마스킹, 알림 최소화, 기록 경계를 설계한다. 구현 방식은 미정이다.
- 완료 기준: 사람과 에이전트의 공통 화면 원칙을 유지하며 스냅샷·타임라인·알림·진단·복사 경로를 검토한다.
  합성 데이터로 줄바꿈·분할 출력·ANSI·중복 값·오탐/미탐을 시험한다.
  화면 마스킹이 셸 history·프로세스 인자·원격 로그의 제거를 보장하지 않음을 명시한다.
  숨김/별표 입력을 수집하지 않고, 정규식만으로 비밀 탐지가 완전하다고 주장하지 않는다.

### PROD-01 · 가치 재현과 외부 사용자 검증

- 범위: 사람이 인증하고, 에이전트가 확인하고, 사람이 작업할 셸이나 방향을 보정한 뒤
  승인·실행·제어 반환으로 이어지는 데모/온보딩 시나리오를 정리한다.
- 완료 기준: EN/KO 자료에서 실제 동작과 재현을 구분한다. 처음 쓰는 사용자의 첫 협업 성공,
  개입 성공, 막힌 지점, 다음 작업에서 재사용 여부를 동의하에 확인한다.
  수집하는 것은 사용성 결과이며 명령·출력·인증정보를 자동 수집하는 분석 기능을 뜻하지 않는다.
  경쟁 우위·안전성·쉬운 사용을 단일 에이전트 후기만으로 보장하지 않는다.

## 작업 순서와 관리

1. UX-01을 재현하고 UX-02/03의 공통 상태·표현을 정리한다.
2. UX-04/05로 첫 연결과 재접속의 막힘을 줄인다.
3. UX-06을 점검하고 UX-07/SEC-01을 별도 설계한다. PROD-01로 반복 사용 근거를 모은다.

각 항목은 구현 시 담당 변경/이슈와 재현 환경, 관찰 결과를 연결하고 `미착수 → 설계 → 구현 → 검증 → 완료`로 갱신한다.
실기 검증이 남아 있으면 완료와 구분한다. 이전 TUI 입력 문제와 네이티브 인수 검증은
[기존 리팩터링 계획](collaboration-refactor-plan.ko.md)의 별도 후속 과제로 유지한다.
