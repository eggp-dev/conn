## 구현한 경계

| 소유자 | 책임 |
| --- | --- |
| `packages/ui` / `@conn/ui` | ConnApp 하나, 공통 컴포넌트·한영 문구, 앱별 룬 상태·요청·타이머·정리, 터미널 렌더링·명령 순서·출력 복구 |
| `frontends/tauri` | 얇은 네이티브 시작 화면, IPC·알림·클립보드/링크·업데이트 포트 |
| `frontends/web` / `@conn/web` | 얇은 브라우저 시작 화면, 쿠키 인증·WebSocket 전송·호스트 업데이트 안내 |
| `crates/frontend::AppRuntime` | 공통 소유자 명령, 연결 epoch, 세션별 입력·응답·resize 순서, 중복 실행 방지·결과 조회·독립 출력 전달 |
| `crates/web` / `conn-web` | 루프백 프로세스 소유자, 인증한 화면 연결, 정적 UI 제공·서버 수명 |
| `crates/core` | 기존 PTY·정책·공유·제어권, 소유자 화면 체크포인트·셸 프롬프트 수명 수정 |

기존 `crates/browser-harness`, 데스크톱의 browser-test 모드, 테스트 전용 전송과 대체 앱 픽스처는 제거했습니다. 순수 UI 검사는 공통 UI와 함께 옮겼습니다. 협업 검사는 같은 빌드의 지속 `conn mcp` 프로세스, 실제 Rust PTY, 빌드된 웹 UI를 사용하며 소유자 결정은 실제 화면으로 조작합니다.

새로고침은 기존 세션에 재연결합니다. 명시적 인계는 입력·크기를 담당하는 화면 하나를 옮기며 에이전트 권한을 부여하지 않습니다. 대기 입력을 무조건 재전송하지 않습니다. 체크포인트와 순번이 있는 출력으로 화면을 복원하고 누락이 생기면 복구까지 입력을 막습니다. 체크포인트는 에이전트 관찰 API가 아니며 에이전트는 허용된 현재 그리드를 계속 봅니다.

순서가 있는 작업의 결과가 불확실하거나 순서 처리가 실패한 경우, 초기·복구 체크포인트를 받지 못한 경우에는 해당 연결을 중단하고 명시적 재연결을 안내합니다. 대기 입력은 폐기하며 다시 연결한 뒤 터미널과 현재 요청 상태를 확인하고 재시도하도록 안내합니다. 소켓 종료 알림이 대기 중인 입력의 실패 응답보다 먼저 도착하는 경우에도 적용합니다. 기존 웹 쿠키를 사용하는 재연결은 자동 인계를 요청하지 않습니다.

공유 전환은 사적인 명령 맥락에 대한 지식을 초기화하므로 첫 명령에 환경 검토가 필요할 수 있습니다. 실제 셸 완료가 확인되면 일반 프롬프트 상태를 다시 판단합니다. 연결 승인·공유·제어권·명령 승인은 별개로 유지합니다.

## 남은 범위

macOS WebKit·IME·네이티브 알림이나 사용자의 실제 SSH 게이트웨이 경로를 검증한 결과는 아닙니다. 이 Linux 호스트에는 GTK 개발 라이브러리가 없어 네이티브 Rust 데스크톱 컴파일을 완료하지 못했습니다. 네이티브 프런트엔드 빌드와 구분합니다.

현재 패키지는 로컬 루프백용입니다. 원격 인증·TLS·다중 사용자 운영·별도 데스크톱 인스턴스 미러링은 구현하지 않았습니다. 서버가 종료되면 PTY도 끝나며 프로세스 재시작이 이를 복구하거나 권한을 되살리지 않습니다. 고급 문자 집합·사용자 지정 탭 간격·OSC 링크 등은 이번 체크포인트 호환성 검증 범위 밖입니다.
