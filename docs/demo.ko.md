## 하나의 작업을 번갈아 이어가기

왼쪽은 실제 Codex CLI 세션이며 오른쪽은 에이전트와 사용자 역할이 함께 쓰는 Conn 터미널입니다. 대화는 Codex에서 이어가고, 두 참여자는 같은 터미널에서 작업합니다.

1. **에이전트가 작업합니다.** Codex가 Conn에서 할인 계산 테스트의 실패를 읽고 제어권을 요청합니다. 계산을 수정한 뒤 테스트 2개가 통과하는지 확인합니다.
2. **사용자 역할이 이어받습니다.** 터미널에 직접 입력해 제어권을 가져오고, 미리 준비한 세 번째 테스트를 추가합니다. 할인율이 125%일 때 가격이 0이어야 하는 조건입니다. 테스트를 실행하자 결과가 `0` 대신 `-30`으로 나옵니다.
3. **에이전트가 계속합니다.** “I added an edge case. Read the terminal and continue.”라고 요청합니다. Codex는 Conn으로 바뀐 화면과 새 테스트를 읽고, 가격이 0보다 작아지지 않도록 수정합니다. 테스트 3개가 모두 통과하는지 확인한 뒤 제어권을 반환합니다.

에이전트는 이어가라는 요청을 받으면 새 상태를 읽습니다. Conn의 스냅샷 도구로 화면을 전달받으므로, 터미널 출력을 대화창에 직접 복사해 붙여 넣는 과정은 필요하지 않습니다.

## 제작 방법

- **Codex CLI 0.153.0**, **gpt-6-astra**, medium 추론 설정으로 실행한 세션을 Conn의 MCP stdio 서버에 연결했습니다. 모델이 실제 터미널 상태에 따라 명령을 선택하며, 데모용 드라이버로 에이전트 명령을 미리 등록하지 않았습니다.
- 별도의 데모 프로젝트, 미리 준비한 추가 테스트와 프롬프트, 독립된 세션 데이터를 사용합니다. 사용자 역할의 승인과 터미널 입력은 브라우저 자동화로 수행하며 별도의 사람이 참여한 것처럼 표현하지 않습니다.
- 촬영용 PTY 브리지로 실제 Codex CLI를 표시하고, 그 옆에 기존 Conn Svelte 프런트엔드를 그대로 배치했습니다. Conn은 Ubuntu에서 로컬 브라우저 테스트 어댑터를 통해 네이티브 Rust 백엔드를 사용합니다. 이 분할 화면은 촬영을 위한 배치이며, 사용자는 Codex와 Conn을 각자의 창에서 실행합니다.
- 화면은 실제로 녹화했습니다. 고정된 분할 화면으로 대화와 공유 터미널을 함께 보여주고, 자막과 컷 편집으로 대기 시간을 줄였습니다. 완성 영상은 세션을 편집한 기록이며 전체 대화록은 아닙니다.
- 영문판과 한국어판은 같은 세션 영상을 사용하고 편집 문구를 각 언어로 제공합니다.
- 저장소에서는 대표 이미지에 MP4 파일 링크를 연결합니다. GitHub 안에서 바로 재생되는 플레이어를 보장하는 방식은 아니며, 추후 호스팅된 첨부 영상으로 링크를 바꿀 수 있습니다.

[촬영 구성](../media/demo/RECORDING.md)과 [브라우저 테스트 어댑터](browser-testing.md)를 참고하세요. 촬영한 협업 흐름은 Ubuntu에서 확인했으며, 이 영상이 Linux·macOS·Windows의 네이티브 설치 프로그램 검증을 의미하지는 않습니다.

## 동작을 해석할 때

사람이 터미널에 입력하면 제어권을 회수하고 에이전트의 추가 입력을 막습니다. 이미 실행한 명령을 되돌리거나 실행 중인 프로세스를 종료하지는 않으며, 프로세스 중단에는 터미널의 일반적인 제어 동작을 사용해야 합니다.

요청의 예정 명령은 에이전트가 전달한 의도입니다. 타임라인의 `실행됨`은 셸로 전달했다는 기록이며 종료 상태가 아닙니다. 영상에서는 실제 테스트 출력으로 결과를 확인합니다. 타임라인은 명령과 제어권 변경을 확인하는 기록이며 터미널 출력이나 스크롤백을 저장하지 않습니다.

내 에이전트로 같은 흐름을 경험하려면 [시작하기](getting-started.ko.md)를 따라 해 보세요. 정책과 감사 기록의 범위는 [신뢰 범위](security.md#한국어-요약)를 참고하세요.
