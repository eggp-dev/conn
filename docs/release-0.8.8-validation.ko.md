# 0.8.8 릴리스 검증

[English](release-0.8.8-validation.md) · [원인 조사](terminal-input-candidates.ko.md) · [Vim 조사](vim-input-investigation.ko.md)

2026-09-23. 소스 검증 기록이다. 태그의 GitHub Actions 실행과 내려받은 배포
파일로 빌드·서명·공증·공개 배포를 별도 확인하며, 이 문서는 그 성공을 미리 선언하지 않는다.

## 수정 내용

- 정책과 승인에 에이전트가 입력한 전체 명령을 사용한다. 지원되는 ASCII 커서
  편집은 커서 양쪽 문자열을 보존한다. 불확실한 자동완성·히스토리·Unicode 편집은
  화면 한 행으로 전체 명령을 추정하지 않고 제출을 중단한다. 사람 입력 내용은
  여전히 저장하지 않는다.
- 거절·만료는 권한부터 취소한다. 확인된 로컬 유휴 셸에서만 Ctrl-C로 정리하고
  빈 입력 경계가 복원된 뒤 이어간다. 알 수 없는 전경 프로그램은 입력을 보존하고
  `inputRetained`를 알리며, 명시적 복구 전에는 새 에이전트 입력을 붙이지 않는다.
  사람의 개입은 제어권·대기 승인을 취소하고 보이는 줄을 직접 편집·제출한다.
- 입력 write/flush 실패는 `input_outcome_unknown`으로 반환한다. 일부 전달됐을 수
  있는 Enter를 자동 재전송하거나 승인 실행 성공으로 기록하지 않는다. 크기는 로컬
  PTY의 적용·조회가 성공한 뒤에만 게시한다. 원격 SSH 끝점의 적용까지 보장하지 않는다.
- 이전 출력 큐의 콜백으로 새 화면이 준비 완료가 되지 않게 한다. 현재 체크포인트가
  적용될 때까지 입력을 멈추고, 지연되면 복원 상태와 명시적 화면 복구를 제공한다.
  보류된 입력을 자동 재전송하지 않는다.

## 검증

격리된 상태 디렉터리와 합성 데이터로 검사한다. 브라우저 검사는 배포용 공통 UI,
실제 Rust 웹 호스트·PTY, 지속 MCP 연결을 사용한다. 별도 UI·정책 엔진을 대체하지 않는다.

실제 셸에서 승인 명령 전체, 정책 결과,
임시 파일 내용, 취소 후 잔여 입력과 다음 명령을 검사하며, 코어/xterm 화면·커서
일치만으로 의미상 정상이라고 판단하지 않는다.

## 한계와 실패 실험

첫 폐기용 OpenSSH 환경이 UTF-8 대신 POSIX 로케일을 상속해 긴 한글·이모지 화면
비교가 실패했다. 시험 환경을 `C.UTF-8`로 수정한 뒤 전체 입력 검사가 통과했다.
이는 시험 환경 보정이며 임의의 바이트 단위 편집 환경을 고친 제품 수정은 아니다.
사용자 프롬프트를 자동 교체하거나 색상을 제거하지 않는다.

첫 SSH Vim 시험에는 `vi`가 설치돼 있지 않았다. 폐기용 컨테이너에 Vim을 설치한
뒤 편집·저장 검사가 통과했다. WebKit 편집 실행마다 ResizeObserver 경고 1회를
별도 기록했다. 편집 성공만으로 모든 네이티브 환경에서 경고가 무해하다고 단정하지 않는다.

Linux Chromium/WebKit의 Vim 검사는 네이티브 Mac WebKit/Tauri 실기 검증과 다르다.
사용자 Mac의 Vim 무응답, 실제 SSH 게이트웨이, 물리 IME, 설치 앱의 업그레이드·재시작은
이번 세션에서 검증하지 못했다. ANSI 프롬프트 설정·원격 크기는 현장 화면 문제의
다른 원인일 수 있다. 재현한 Conn 결함을 수정하되 모든 사진의 원인을 확정하지 않는다.
출력에 개행을 삽입하거나 모션을 없애지 않으며, 기존 무제한 PTY 출력 큐는 유지한다.
