새 crate, 모듈별 잠금, 플러그인 런타임을 추가하지 않았다. 임베더를 위해 기존 `ipc`의 공개
타입 이름은 재노출한다. AppleScript 용어·이벤트 코드, D-Bus 작업, 외부 응답 형식과 설정
저장 형식은 유지한다.

### 연결 승인과 공유는 별개다

비공개·빈 화면·셸 준비 중·설정창 안에서도 연결 요청을 처리할 수 있다. 비공개 탭에서도
에이전트 설치와 앱 전체 연결 승인 설정을 열 수 있고, 세션 정책은 공유 탭에만 적용한다.
연결을 승인해도 비공개 화면 공개, 참여자 선택, 입력 제어권 부여는 자동으로 일어나지 않는다.

연결 이벤트와 스냅샷에 revision을 부여했다. UI는 누락된 이벤트를 보정하고 오래된 응답이
이미 처리한 요청을 되살리지 않도록 한다. 실패한 요청은 재시도할 수 있으며, 처리 완료 응답이나
권위 있는 스냅샷으로 해소된 요청만 제거한다. 이름이 같은 재연결도 다른 연결 ID를 사용한다.

### 공유 전환은 사전 검증 후 확정한다

살아 있는 참여자 ID 확인과 기록 파일 준비를 먼저 수행한다. 외부 입력의 기존 operation 잠금으로
실제 전달을 막아 둔 상태에서 Session 잠금 안의 사전 검증을 수행한다. 성공한 경우에만 외부
핸들을 회수하고 대기 입력을 비운다. 입력 상태나 기록 자원 때문에 실패하면 비공개 상태·세대·
외부 입력 권한을 유지한다. 공유 대상을 바꾸기 위해 PTY나 프로세스를 새로 만들지 않는다.

내부 소유자 API에 `sharing_state`를 추가하고, 공유 적용에는 선택을 읽은 `expectedRevision`을
전달한다. 오래된 요청은 외부 작성자를 중단하기 전에 `sharing_changed`로 거부한다. UI는 최신
선택을 명시적으로 다시 불러오도록 하며 자동으로 적용하지 않는다. 기존 `sharing_participants`
응답은 유지하고, revision 없는 기존 소유자 호출도 호환된다. 선택한 연결의 수명은 확정 직전에
다시 검사한다.

공유의 잠금 순서는 외부 operation → Session이다. 제어권 전환은 조정 잠금과 복사한 세션
목록을 이용하고, 짧은 동기 전환 중에만 세션 잠금을 유지한다. 목록 잠금은 세션 잠금 전에
해제하며, 사용자 승인을 기다리는 동안 이 잠금들을 유지하지 않는다. 연결 콜백은 레지스트리
잠금을 해제한 뒤 호출하고 Session 잠금을 획득하지 않아야 한다.

### 취소 규칙

| 원인 | 처리 |
| --- | --- |
| 명시적 제어권 회수 | 현재 임대가 없어도 검토·제안·유예·미응답 제어 요청 취소 |
| 에이전트 반환·이동 | 해당 연결의 대기 작업과 임대 정리 |
| 연결 종료 | 해당 연결의 작업만 정리. 같은 이름의 다른 연결은 독립적 |
| 공유 중단·대상 변경 | 기존의 세션 전체 취소 동작을 유지하고 참여 세대 증가 |
| 프로세스 종료·Observe 전환 | 제어권과 대기 작업을 함께 정리 |
| 사용자 타이핑 | 기존 선점 동작과 원시 입력 비수집 경계 유지 |
| 검토 대기·임대 만료 | 기존 검토 중 임대 갱신과 만료 규칙 유지 |
| 창 가림·백그라운드·최소화 | 접근 제한 추가 없음 |

의도적으로 바뀐 동작은 명시적 회수·반환 때 검토와 제안을 정리하고, 회수·프로세스 종료 때
미응답 제어 요청까지 끝내는 것이다. 취소된 검토가 나중에 ENTER를 전달할 수 없다.
기존 TUI `input_pending` 차단 조건은 유지했다. 그 판정 방식의 재설계는 이번 범위가 아니다.

### 공통 UI와 상태 적용

연결 승인·제어권 승인·명령 검토 카드는 같은 표시 컴포넌트를 사용하되 명령과 의미는 구분한다.
키보드·명령 팔레트·카드 버튼은 요청별 진행·오류 상태를 공유한다. 세션과 요청 ID를 호출 전에
고정해, 탭 전환 후 다른 셸에 결과가 전달되지 않도록 했다.

세션 읽기는 중복 실행을 합치고 이벤트와 경합한 응답은 다시 읽는다. 이벤트와 스냅샷은 같은 참여·요청 변환 함수를 사용한다. 전체 상태 갱신으로 누락된
상태와 유예 표시를 복구하며, 유예 타이머는 이벤트 경로와 같은 단조 증가 시계를 사용한다. 참여자 갱신이 공유 오류를 지우지 않는다. 영문·한국어는 i18n을
통하며, 토스트는 승인 버튼을 가리지 않도록 작업 영역 위에 표시한다.

실제 Harness 테스트는 공유 변경 전에 셸 변수를 설정한 뒤, 에이전트 실행 결과로 그 값이
독립된 출력 줄에 나타나는지 확인한다. 단순히 입력 명령이나 이전 출력이 보이는 것만으로는
통과하지 않는다. 임시 소켓·설정을 사용했고 SSH에는 합성 인증 정보만 사용했다. 실험용
컨테이너는 이전의 중지 상태로 돌려놓았다. 로컬 화면 증거는 `artifacts/collaboration-refactor/`에
있으며 공개 소스 목록에는 포함하지 않는다.

### 다시 실행하기

```sh
cargo test --locked
cargo build --locked -p conn-browser-harness
cd frontends/tauri
npm test
npm run build
npm run test:collaboration
npm run test:collaboration:harness
```

브라우저 검사는 잠금 파일에 고정한 Playwright를 사용한다. `frontends/tauri`에서
`npx playwright install chromium`을 먼저 실행한다. CI도 같은 브라우저를 설치하며 두 흐름을
Required checks에 포함한다. 초기 CLI 방식은 CI에서 CDP 연결이 끊겨, 배포 준비 중 지속적인
드라이버와 명시적인 전환 완료 대기로 바꿨다. 검증 항목은 유지했다.

## 남은 네이티브 인수 검증

- **Linux GUI / D-Bus:** `gdk-3.0` 개발 메타데이터가 없어 컴파일 중단. 샌드박스 밖에서도
  확인했다. `.github/actions/setup/action.yml`의 데스크톱 의존성을 준비한 뒤 격리된 네이티브
  어댑터 검증을 수행해야 한다.
- **macOS Apple Silicon:** 이전 SSH 주소의 호스트 키 확인에 실패했다. 신뢰 검증을 우회하지
  않았다. 확인된 맥에서 이 변경본을 빌드하고 앱 종료·실행 상태의 AppleScript, 숨김·마스킹
  인증, 비공개 창의 연결 승인, 같은 세션 공유, 백그라운드 관찰·제어, 회수와 공유 중단을 검증해야
  한다. 다른 설치본이 아닌 빌드한 앱의 스크립팅 사전도 확인해야 한다. 배포에는 서명된 설치본과
  업데이트 검증이 추가로 필요하다.
- **Windows:** 이 환경에는 네이티브 실행 환경이 없다. 기존 Windows CI에서 빌드·테스트 후
  실제 앱에서 MCP 연결 승인·공유·회수·종료·재연결을 확인해야 한다.

브라우저·코어 통과로 위 항목을 대체하지 않는다. 이번 작업 트리의 패키징·서명·설치·업데이트
배포는 검증하지 않았다.
