# 첫 협업 전에 궁금한 점

[English](faq.md) · 한국어 · [직접 해보기](first-collaboration.ko.md) · [Conn으로 돌아가기](../README.ko.md)

## AI 구독을 하나 더 해야 하나요?

Conn은 모델을 실행하거나 모델 이용권을 판매하지 않습니다. 쓰던 에이전트 클라이언트와 계정을 그대로 사용합니다. 모델 제공 여부·요금·클라이언트 권한은 해당 서비스에 따릅니다.

## 에이전트와 어디서 대화하나요?

Codex, Claude Code, Cursor, GitHub Copilot에서 대화합니다. Conn은 MCP나 CLI를 통해 함께 쓰는 터미널을 제공합니다. 클라이언트가 화면을 읽고 제어권을 요청해 같은 셸에서 작업합니다. 직접 개입한 뒤에는 현재 터미널을 다시 읽고 이어가도록 요청하세요.

데스크톱 앱에서 이 로컬 클라이언트들의 연결을 설정할 수 있습니다. Codex는 데스크톱 앱·CLI·IDE 확장의 로컬 작업을 뜻합니다. `~/.codex/config.toml`에 등록한다고 별도 ChatGPT 앱에 연결이 추가되지는 않으며, 웹·클라우드 작업에서도 이 로컬 stdio 서버에 접근할 수 없습니다. [에이전트 연결 안내](agent-integrations.ko.md)

## 터미널을 함께 쓰면 무엇이 좋은가요?

작업 폴더를 바꾸거나, 빠진 테스트를 추가하거나, 대화형 단계를 직접 마칠 수 있습니다. 에이전트는 복사해 붙인 설명 대신 바뀐 작업 상태를 다시 읽고 이어갑니다. 같은 셸에서 작업을 지켜보며 참여하고 싶을 때 유용합니다. 개입 없이 맡기는 작업이라면 이 흐름이 필요하지 않을 수도 있습니다. [협업 이야기 읽기](collaboration-story.ko.md)

## 직접 입력하면 실행 중인 명령도 멈추나요?

직접 입력하면 제어권을 되찾고 에이전트의 추가 입력을 막습니다. **이미 실행 중인 프로세스를 종료하거나 끝난 작업을 되돌리지는 않습니다.** 필요한 경우 Ctrl-C처럼 해당 프로그램에 맞는 일반 터미널 조작으로 중단하세요. Conn 밖의 다른 도구를 사용하는 에이전트까지 막는 것은 아닙니다.

제어권 승인과 명령 실행 승인은 별개입니다. 제어권을 허용해도 명령 정책이 유지됩니다.

## 에이전트가 참여해도 되는지 왜 묻나요?

일반 탭은 허용한 모든 에이전트 연결에 열려 있습니다. 그래서 새 연결이 나타나면 Conn이 한 번 묻습니다. **허용** 또는 **거부**입니다. 답하기 전까지 그 연결은 세션에 대해 아무것도 알 수 없습니다. 허용은 그 연결에만 적용되며, 클라이언트가 다시 연결하거나 같은 클라이언트의 다른 창이 연결하면 다시 묻습니다. 내 PC의 에이전트를 모두 신뢰한다면 **설정 → 에이전트**에서 이 확인을 끌 수 있습니다. 외부 실행 도구가 시작한 세션은 직접 공유하기 전까지 비공개입니다.

## 다른 것을 보는 동안에도 에이전트가 계속 작업하나요?

v0.8.0부터 그렇습니다. Conn을 최소화했거나, 다른 앱 뒤에 있거나, 다른 탭을 보고 있어도 에이전트는 자기가 묶인 세션을 읽고 작업합니다. 내가 다른 탭으로 옮겨도 따라오지 않습니다. 에이전트를 제한하는 것은 공유 여부, 선택한 모드, 명령 정책과 승인, 그리고 제어권입니다. 내가 입력하면 제어권은 즉시 돌아오고, 에이전트는 한 번에 한 탭에서만 제어권을 가집니다. 세션을 읽지 못하게 하려면 공유를 중단하고, 입력만 막으려면 Observe 모드를 쓰세요.

## 무엇부터 해보면 좋나요?

[작업 폴더를 함께 바꿔보세요](first-collaboration.ko.md). 임시 로컬 작업 공간과 작은 파일 하나, 쓰던 에이전트로 진행합니다. SSH 서버나 원격 컴퓨터는 필요하지 않습니다. 에이전트가 새 위치를 확인하고 그곳에서 마무리하면 첫 제어 전환에 성공한 것입니다.

## 에이전트에게 암호가 보이나요?

일반 세션에서 화면 조회가 허용된 에이전트는 Observe 모드를 포함해 터미널 화면에 보이는 내용을 읽을 수 있습니다. 숨겨진 암호 입력을 명령 이력으로 복원하지는 않지만, 프로그램이 암호를 출력하면 화면에 남을 수 있습니다. `*****` 표시는 실행한 프로그램의 동작이며 Conn의 비밀정보 탐지 기능이 아닙니다.

에이전트가 보낸 명령·사유·요청 원문은 감사 로그와 타임라인에 저장될 수 있습니다. 여기에 인증정보를 넣지 마세요. 화면 조회를 다시 켜면 화면에 남은 이전 출력이 보일 수 있습니다. [신뢰 모델](security.md)

## 타임라인에는 무엇이 남나요?

에이전트 명령과 협업 결정, 요청 원문·승인·거절이 남습니다. 통합된 로컬 Bash/Zsh에서는 실행이 시작된 명령과 확인 가능한 완료 상태도 기록합니다. 원시 타이핑·암호 입력·편집기 입력으로 사람의 명령 이력을 추정하지 않습니다.

타임라인은 화면 녹화나 실행 중인 프로세스의 백업이 아닙니다. 명령 인자 자체에 민감정보가 들어갈 수 있습니다. 지원하지 않는 셸이나 충돌하는 셸 훅에서는 사람 명령이 기록되지 않을 수 있으며, 대신 키 입력을 수집하지 않습니다. [셸 통합](shell-integration.ko.md)

## SSH에 접속한 뒤에도 협업할 수 있나요?

일반 세션의 화면·제어 권한 범위에서 계속할 수 있습니다. Conn은 공유 터미널 안의 SSH 클라이언트를 조작합니다. 로컬 셸 통합은 바깥쪽 `ssh` 명령을 기록하며, 원격 훅을 설치하거나 원격 셸에서 사람이 실행한 명령을 자동 기록하지 않습니다. 원격 프로필에서는 명령 검토가 필요합니다. [프로필과 실행 범위](backends.md)

## 외부 자동화 세션도 에이전트와 공유하나요?

외부 비공유 세션은 용도가 다릅니다. 에이전트의 목록 조회·화면 조회·제어 대상에서 제외되며 Conn 활동 기록을 만들지 않습니다. 사람이 제어권을 가져와도 자동으로 공유되지는 않습니다. 미배포 공유 화면 버전에서는 소유자가 참여자를 선택하고, 인증된 같은 연결을 별도로 공유할 수 있습니다. 자식 프로그램 출력·셸 이력·OS의 다른 저장 경로는 별개입니다. [외부 자동화](external-automation.ko.md)

## 업데이트는 어떻게 하나요?

v0.6.0부터 백그라운드에서 서명된 업데이트를 확인하고 내려받습니다. 준비되면 **설치하고 다시 시작**을 선택하세요. 설치 시 현재 셸 세션은 종료됩니다. **업데이트 확인 → 업데이트 설정**에서 자동 동작을 바꿀 수 있습니다.

앱 내 설치는 Apple Silicon macOS·Windows x64·Linux AppImage에서 지원합니다. `.deb`는 새 패키지나 패키지 관리자로 업데이트합니다. 시스템 패키지는 관리자 권한 없이 스스로를 교체할 수 없기 때문입니다. Linux에서 앱 내 업데이트를 원하면 AppImage를 선택하세요. 기존 0.5.x는 0.6.0을 한 번 직접 설치해야 합니다. [설치·업데이트 안내](getting-started.ko.md)

## 어떻게 도움을 줄 수 있나요?

첫 협업을 해보고 막힌 단계나 직접 개입하고 싶었던 순간을 알려주세요. Conn 버전·OS·셸·클라이언트와 공개 가능한 작은 재현 예제가 도움이 됩니다. 화면과 요청 원문은 공유 전에 검토하세요. 터미널 전체 덤프가 필요한 경우는 드뭅니다. [문제 제보](https://github.com/eggp-dev/conn/issues/new/choose) · [기여하기](../CONTRIBUTING.ko.md)
