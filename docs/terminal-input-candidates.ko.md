# 터미널 입력·줄바꿈 조사와 수정 후보

[English](terminal-input-candidates.md)

2026-09-23 · 조사 기준 `05b6214` / 0.8.7 소스. **분석 결과이며 제품 수정·macOS 검증·배포 완료 보고가 아니다.** 기존 Vim 조사 변경은 보존했다.

## 결론과 증거 범위

사용자 사진의 원인을 한 가지로 확정하지 않는다. 개행 없는 출력, 입력 줄의 재그리기, 승인 대상 명령의 식별, 취소 후 남은 입력은 서로 다른 문제다. 색상 설정과 무관하게 Conn에서 재현되는 결함도 발견했다.

실험은 Linux Chromium, 빌드된 공통 웹 UI, 실제 Rust 웹 호스트·Bash PTY, 지속적인 MCP 연결을 사용했다. 승인·거절은 실제 공통 UI를 조작했다. 파일은 임시 시험 디렉터리의 합성 데이터만 사용했고 사용자 Mac·원격 서버·인증 입력에는 접근하지 않았다. 아래 커서 이동은 별도 설명이 없으면 MCP의 LEFT 키다.

## 우선 수정 후보

### A. 승인 대상 명령의 완전성과 출처 보존 — P0

`crates/core/src/input.rs:156`은 추적이 불확실해지면 커서가 있는 **화면 한 행**에서 명령을 복원한다. 줄바꿈된 명령의 뒷부분을 전체 명령으로 오인할 수 있다. `strip_prompt`는 셀 단위 `prompt_col`을 `Vec<char>` 인덱스로 사용해 한글·전각 문자에서 다른 오류를 만든다. `session.rs:1766`은 이 결과로 정책을 판단하지만 실제 제출은 PTY에 Enter를 보내므로 전체 물리 입력이 실행된다.

재현 명령은 `printf '%s\n' > probe.out 'WRAP_BEGIN_…_END'`이며 중간은 합성 문자 200개다. 편집 없는 경우 승인 대기·파일 없음, LEFT 한 번 후에는 반환 명령이 `…_END'`로 축약되고 승인 없이 전체 파일 기록이 실행됐다. 삭제나 운영 파일을 사용하는 실험은 하지 않았다.

권장 방향:

- 확실히 추적되는 에이전트 입력과 불확실한 입력을 구분한다. 현재 화면 한 행이나 과거 입력을 임의로 완전한 명령으로 승격하지 않는다.
- 지원하는 편집은 커서 위치와 함께 추적하고, 화면에서 복원할 때는 셀 폭·실제 줄바꿈 정보·확인된 프롬프트 경계를 사용한다. 화면 밖 기록이나 숨겨진 텍스트로 부족한 정보를 채우지 않는다.
- 전체 명령을 확인할 수 없는 경우 그 조각으로 정책을 판단하거나 승인을 받아 Enter를 보내지 않는다. 해당 입력만 다시 확인·정리하는 흐름을 제공한다. 일반 명령의 자동 실행이나 SSH 전체를 일괄 제한하지 않는다.
- 승인 카드, 정책 평가, 실행·감사 기록이 같은 명령 출처를 사용하도록 한다. 단순히 dirty 플래그를 무시하고 원래 입력만 신뢰하는 변경은 제외한다.

완료 기준: 줄바꿈 후 LEFT/RIGHT/Backspace/Tab/히스토리, 한글·결합 문자 프롬프트, 화면보다 긴 입력에서 부분 문자열이 승인·정책의 전체 명령이 되지 않는다. 정상적인 일반 명령 자동 실행은 유지한다.

### B. 취소와 물리 입력 정리를 분리 — P1

`session.rs:1985`의 거절·만료는 Ctrl-U를 보내고 바로 추적 상태를 초기화한다. Bash 기본 편집에서 Ctrl-U는 커서 앞쪽을 지우며 뒤쪽은 남을 수 있다. 같은 함수가 사람 개입·연결 해제·제어 반환 등에서도 사용되므로 영향 범위는 거절 버튼 하나보다 넓다. 정책 자체의 Deny 경로에도 같은 가정이 있다. 사람 입력 추적 코드는 이미 Ctrl-U만으로 빈 입력을 단정하지 않지만 에이전트 승인 취소는 그 기준을 공유하지 않는다.

권장 방향: 승인 취소는 즉시 확정하되 실제 입력은 별도 상태로 보존한다. 확인된 셸 편집 상태에서 안전하게 전체 입력을 취소하고 **출력에서 빈 경계가 확인된 뒤** 추적을 초기화한다. 확인할 수 없으면 남은 입력을 그대로 보여주고 정리가 필요함을 표시한다. 그 상태에 새 에이전트 명령을 이어 붙이지 않는다. 편집기·다른 전경 프로그램에 Ctrl-C나 편집 키를 일괄 주입하지 않는다. 사람 개입의 원시 입력 내용은 보관하지 않는다.

완료 기준: 커서 앞·중간·끝, 여러 줄 입력에서 거절·만료·제어 반환·연결 종료·사람 개입 후 숨은 잔여 명령이나 자동 재실행이 없다. 취소 실패가 영구적인 설명 없는 `input_pending`으로 남지 않는다.

### C. PTY I/O 성공과 화면 상태의 대응 강화 — 우선 보강

`session.rs:1092`는 먼저 화면 모델 크기를 변경하고 출력 프레임을 보낸 뒤 PTY resize 오류를 무시한다. `write_pty`도 write/flush 결과를 버린다. UI 큐의 요청 순서가 맞는 것과 실제 PTY 처리가 성공한 것은 다르다.

권장 방향: resize 실패를 호출자에게 전달하고 실패한 크기를 확정하지 않는다. 요청 크기·로컬 PTY 적용 크기·화면 적용 크기를 구분해 내용 없는 진단을 제공한다. 입력 전송이 부분 성공했을 수 있으면 성공으로 보고하거나 자동 재전송하지 않는다. 원격 크기는 로컬 PTY 검사만으로 보증하지 않는다.

크기 대조 실험에서는 같은 입력의 커서가 0부터 세어 `(행 3, 열 12)`에 있었다. LEFT 30회 후 정상 대조군은 `(행 2, 열 86)`, PTY만 80열인 경우는 `(행 3, 열 0)`이었다. 두 경우 모두 코어/xterm 화면·커서 일치 검사는 통과했다. 승인 패널 개방은 두 경우 모두 PTY를 18행·104열로 바꿨다. 크기 불일치 자체는 시험이 주입한 것이며 Conn이 사용자 환경에서 그 불일치를 만들었다는 증거는 아니다.

완료 기준: 실패하는 PTY 어댑터와 실제 SSH 시험에서 크기 적용 실패를 검출한다. 고정 창의 패널 반복·빠른 열기/닫기·장문 출력 중 입력과 크기 변경 순서를 확인한다. 매 프레임 resize하거나 지연만 늘리는 변경은 제외한다.

### D. 화면 재동기화의 세대와 준비 상태 보호 — 범위가 작은 보강 후보

`packages/ui/src/lib/terminalOutput.ts:18`의 이전 write 완료 콜백은 `clear()` 후에도 실행된다. `Term.svelte`의 체크포인트 완료 콜백은 `mounted`만 확인하고 `renderReady=true`로 바꾼다. 이전 연결/복원 세대의 완료가 새로운 준비 상태를 바꾸지 못하도록 세대 검증을 추가하는 방향이 타당하다.

체크포인트 대기 중 입력을 조용히 버리는 상태가 오래 지속되는지도 확인해야 한다. 복원이 지연되면 기존 연결 UI에서 상태와 명시적 재연결을 제공하고 입력을 자동 재전송하지 않는다. 입력 내용 없이 포커스·준비 여부·큐 진행·전송 완료 여부만 진단한다. 이는 Vim 미응답을 조사하기 위한 후보이며 원인 확정이 아니다.

완료 기준: 지연된 이전 체크포인트 완료, 연결 종료와 즉시 재연결, Vim 실행 중 화면 재연결을 검사한다. 오래된 콜백이 준비 상태를 복구하지 않고 현재 체크포인트 적용 후에만 입력을 받는다.

## 이번 패치에 포함하지 않을 추측성 변경

- 사용자 PS1 자동 교체, 색상 일괄 제거, 원격 환경 탓으로 종결.
- 모든 출력에 개행 추가. JSON 뒤 프롬프트가 붙는 것은 본문 끝 개행 유무를 먼저 확인한다.
- 모션 전체 제거, 고정 80열 강제, 셸이 처리했는지 확인하지 않는 resize 재시도.
- 일반 셸 입력과 Vim 입력을 같은 장애라고 단정하거나 Linux 웹 검사로 Mac 수정 완료 선언.

## 검증 묶음과 제안 순서

**A와 B를 첫 수정 묶음으로 권장한다.** C는 실패 계약을 명확히 하는 보강으로 함께 설계하고, D는 이전 콜백의 세대 경계를 독립적으로 검증해 적용한다. 올바른/잘못된 색상 프롬프트 비교는 검증 묶음에 포함하되 사용자 설정 자동 수정을 제품 기능으로 추가하지 않는다.

최종 검증은 UI·코어 화면 일치뿐 아니라 의도한 커서 위치, 승인에 표시된 전체 명령, 정책 결과, 실제 합성 출력/파일, 취소 후 잔여 입력을 함께 확인한다. 로컬과 실제 폐기 가능한 SSH, 일반/색상/한글/여러 줄 프롬프트, 긴 입력 편집과 승인·거절·사람 개입, 고정 창 패널 반복, 네이티브 Mac Vim 편집·저장이 필요하다. SSH 게이트웨이 환경과 물리 IME는 별도 근거가 필요하다.

이 조사에서 추가한 두 웹 진단 스크립트와 합성 스크린샷·JSON은 `/tmp/conn-terminal-investigation/`에 보존했다. 스크립트 출력의 `PASS`는 캡처·코어/렌더러 일치 성공이며 의미상 올바른 입력을 보증하지 않는다. 정식 회귀 테스트에는 올바른 동작을 기대하는 assertion을 추가해야 한다.
