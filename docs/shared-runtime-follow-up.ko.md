## 받아온 변경

`codex/shared-runtime-macos-validation`을 `7fa5723`에서
`5df5e3667ebb6a820fc8ac5e6b544beb7b68fe52`로 fast-forward했다.
다른 브랜치 병합·메인 병합·태그·배포는 하지 않았다. 기존 미커밋 설계 문서 7개는
받기 전후 SHA-256이 같았으며, 이후 작업 정리 링크만 추가했다.

| 커밋 | 내용 |
| --- | --- |
| `1d30c87` | 긴 입력에서 PTY 출력 읽기가 입력 쓰기의 세션 잠금을 기다리던 교착 수정. FIFO 소비자와 사람·에이전트 회귀 검사 추가 |
| `5df5e36` | macOS 네이티브·웹 실기 결과, 검증 스크립트 보완, 증거 이미지 12장 |

Mac 이미지 12장의 SHA-256은 저장소의 증거 매니페스트와 모두 일치했다.
이는 증거 파일 무결성 확인이며 이 Linux 실행에서 Mac 검사를 다시 했다는 뜻이 아니다.

## Linux에서 발견하고 보완한 검사 문제

원격 HEAD 그대로 실행한 첫 `cargo test --locked`는 새 회귀 검사 2개에서 실패했다.
긴 입력과 전체 출력, 다음 명령은 완료됐지만 Linux Bash/readline이 명령 출력 앞에
bracketed-paste 모드 제어 문자를 넣었다. 검사에서 기대한 연속 원시 바이트
`CRLF + NEXT_OUTPUT_OK + CRLF`와 일치하지 않아 시간 초과로 판정됐다.

`crates/core/tests/shell_integration.rs`의 후속 출력 확인을 코어의 현재 터미널 그리드에서
`NEXT_OUTPUT_OK`가 독립된 행인지 검사하도록 보완했다. 입력 쓰기의 5초 제한과
3KB 전체 출력 검사는 유지했다. 명령 에코만으로는 새 조건을 통과할 수 없다.
런타임 수정은 추가하지 않았으며 이 검사 보완은 아직 로컬 미커밋 변경이다.

## 이번 Linux 회귀 결과

환경: Linux, Rust 1.95.0, Node 26.8.1. `npm ci`를 다시 실행했다.
아래는 `5df5e36`과 위 테스트 보완을 기준으로 한 결과다.

| 검사 | 결과 | 범위 |
| --- | --- | --- |
| `cargo test --locked` | **274 PASS, 1 ignored** | 기본 워크스페이스 멤버. 네이티브 Tauri 제외; zsh 미설치 사례 내부 skip |
| `cargo build --locked -p conn-web -p conn` | **PASS** | 실제 Rust 웹 호스트와 MCP CLI |
| `npm run build:web` | **PASS** | Svelte 오류 0, 기존 경고 17개와 번들 크기 경고 유지 |
| `npm run test:ui` | **65 PASS** | 공통 UI 상태·동작 |
| `npm run test:collaboration` | **8 PASS** | 빌드된 공통 웹 UI·실제 Rust·지속 MCP, 페이지 오류 없음 |
| `npm run test:input -w @conn/collaboration-tests` | **23 PASS** | 로컬 Bash 입력·렌더링. 이번 실행은 SSH 픽스처를 지정하지 않음 |
| `npm run test:screen -w @conn/ui` | **85 PASS** | 코어/xterm 현재 그리드·커서 비교 |
| `npm run test:checkpoint -w @conn/ui` | **984 PASS** | 체크포인트 복원·후속 출력·크기 변경 |
| `npm run test:app-lifetime -w @conn/ui` | **PASS** | 실제 공통 UI + 통제한 호스트/IPC 픽스처. 네이티브 OS·실제 PTY·MCP 검사는 아님 |
| 생성 owner 계약 / 공통 UI 의존성 경계 | **PASS / PASS** | Rust/TS 계약 일치, 얇은 앱 진입점 유지 |

의존성 설치가 보고한 기존 low 등급 항목 2개는 강제 업데이트하지 않았다.
이번에 Linux 네이티브 앱, 물리 IME, 사용자 서버, 시스템 알림을 재검증하지 않았다.
Mac의 실제 루프백 SSH 24개 결과는 Mac 보고서에 속하며 위 Linux 수치에 합산하지 않는다.

## 완료와 미완료를 나누는 기준

완료된 것은 공통 UI·런타임 리팩터링, Mac에서 발견한 긴 입력 교착 수정, 보고서에 명시된
Mac 실기 경로, 위 Linux 회귀다. 설치된 공개 v0.8.6에 이 미배포 브랜치 변경이 들어갔다고
표현하지 않는다. Mac의 승인 단계 기능 PASS도 단계의 구별성과 사용자 이해도 PASS를 뜻하지 않는다.

| 남은 작업 | 판단 / 다음 완료 기준 |
| --- | --- |
| **P1 · 사람 입력 상태 판정** | [#65](https://github.com/eggp-dev/conn/issues/65). 빈 프롬프트를 막는 경우와 남은 사람 입력에 에이전트 입력이 붙는 경우를 함께 해결. 제어 문자 끝 바이트만 보는 현행 판정이 남아 있음 |
| **P1 · 승인 요청 상태의 일관성** | 승인 사유·대상·범위·가능한 버튼을 하나의 일관된 상태로 전달. 지연된 세션 상태가 같은 요청의 버튼·설명을 바꾸지 않게 하고 서버의 최신 권한 검사는 유지 |
| **P1 · 승인 이유의 정확성** | 명령 위험과 셸 맥락 불확실성을 구분. 복합 명령을 통한 SSH 진입 차이를 별도 재현하고 설명; 비공유나 플랫폼 UI 차이로 단정하지 않음 |
| **제어 UX · 합의한 방향의 구현** | 오른쪽 Conn 뱃지에서 Morphing Dialog처럼 제어권 요청이 확장·복귀. 명령 실행 검토는 하단 유지. 공통 컴포넌트·룬으로 구현하고 반복·다른 탭·키보드·동작 줄이기 검증 |
| **출시 전 런타임 부하 검증** | 무제한 출력 큐의 장시간·대량 출력·느린 소비자에서 메모리, 지연, 종료 시 마지막 출력 순서 측정. 단순히 대기형 유한 큐로 바꾸면 교착을 재도입할 수 있음 |
| **Linux 설치판 시작 문제** | 이 대화에서 확인한 렌더러 환경 변수 우회는 로컬 조치. 이번 Mac 커밋은 설치판 수정이나 다른 장치의 동작 검증을 포함하지 않음 |
| **환경별 인수·릴리스** | 실제 사용자 SSH 게이트웨이, 물리 IME, 네이티브 알림, 네이티브 IPC 장애 주입과 배포 서명·공증·업데이트 산출물은 별도 검증 |

작업 순서는 **입력·승인 상태의 정확성 → 합의한 제어 UX 구현 → 같은 실제 경로의 인수 검증**으로
잡는다. 출력 큐 부하 검증은 독립된 출시 전 항목이다. 새 UI가 오래된 상태 결함을 가리거나
일반적인 반복 작업마다 다시 승인하게 만들어서는 안 된다.

현재 로컬 변경은 제품 불변식·제어 UX 설계·작업 정리 문서와 Linux 회귀 테스트 보완이다.
새 모핑 UI 구현, 커밋·푸시, 메인 병합·태그·배포는 이번 인수 작업에 포함하지 않았다.
